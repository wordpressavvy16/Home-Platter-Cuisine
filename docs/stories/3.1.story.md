
# Story 3.1: AI-Powered Natural Language Search

-   **Epic:** 3 (Customer Marketplace & Discovery Engine)
-   **Status:** Done

---

### User Story:
As a Customer, I want to search for kitchens and meals using everyday language, so that I can easily find options that match my specific cravings, dietary needs, or preferences without needing to use rigid keywords.

---

### Acceptance Criteria:

1.  **Given** a user is on the `HomePage`,
    **When** they see the search bar,
    **Then** the placeholder text should encourage natural language queries (e.g., "healthy vegetarian options with good ratings").

2.  **Given** a user types a query like "highly rated chicken dishes" into the search bar and clicks "Search",
    **When** the search is initiated,
    **Then** a loading indicator must appear while the AI processes the query.

3.  **Given** the AI processes the query,
    **When** it returns structured criteria (e.g., `{ keywords: ["chicken"], minRating: 4.5 }`),
    **Then** the list of providers must be filtered based on this structured data.

4.  **Given** the search query "highly rated chicken dishes",
    **When** the results are displayed,
    **Then** only kitchens with an average rating of >= 4.5 AND that have "chicken" in their name, cuisine, or menu items should be shown.

5.  **Given** the search query "vegan food",
    **When** the results are displayed,
    **Then** only kitchens offering meals marked as `VEGAN` should be shown.

6.  **Given** the `MealIdeaGenerator` component exists,
    **When** this story is implemented,
    **Then** the `MealIdeaGenerator.tsx` file and its usage in `HomePage.tsx` must be removed to avoid redundancy.

---

### Technical Specification:

-   **AI Service (`services/geminiService.ts`):**
    -   Create a new function `getSearchCriteriaFromQuery(query: string): Promise<SearchCriteria>`.
    -   This function will call a new backend endpoint `/api/ai/natural-search`. The call to the actual Gemini API will happen on the secure backend.
    -   The backend will use the Gemini API with a `responseSchema` to parse the user's `query` into a `SearchCriteria` object. The schema should define properties for `keywords: string[]`, `minRating: number`, and `mealType: MealType`.
    -   The `generateMealIdea` function and its related mock endpoint will be removed.

-   **Mock API (`api/mock.ts`):**
    -   Implement a mock handler for `POST /api/ai/natural-search`.
    -   This handler should inspect the incoming `query` string and return a plausible, hardcoded `SearchCriteria` object for testing purposes (e.g., if query contains "veg", return `{ mealType: 'VEG' }`).

-   **UI (`components/HomePage.tsx`):**
    -   Remove the `<MealIdeaGenerator />` component.
    -   Convert the search input into a `<form>` with a "Search" button containing a `<SparklesIcon />`.
    -   Implement an `onSubmit` handler for the form (`handleSearch`).
    -   This handler will set an `isSearching` state to `true`, call `getSearchCriteriaFromQuery`, and store the result in a new state variable `searchCriteria`.
    -   The `filteredProviders` `useMemo` hook must be rewritten to perform complex filtering based on the `searchCriteria` object. It should check against provider rating, meal types in the menu, and keywords across the provider's name, cuisine, and menu item details.

# Story 24.1: Frontend - Connect to Live AI Gateway Service

-   **Epic:** 24 (Live Backend - AI Gateway & Services Migration)
-   **Status:** Done

---

### User Story:
As a Frontend Developer, I need to update the application to route all AI-related API calls to the new live AI Gateway Service, so that we can remove client-side API key exposure and use the secure, production AI backend.

---

### Acceptance Criteria:

1.  The application's API calls for all AI features (e.g., `/api/ai/*`) are now directed to the live backend endpoint (`https://api.homeplatter.com`) instead of the internal mock server.
2.  All other API calls that still rely on the mock server must continue to function correctly.
3.  The `api/client.ts` "switch" logic is updated to selectively route all AI-related requests to the live backend.
4.  All components that use AI services (`HomePage.tsx`, `AnalyticsPage.tsx`, `SupportChatbot.tsx`, etc.) work seamlessly with the new live AI Gateway.
5.  The client-side Gemini SDK is completely removed from the application to eliminate the security risk of an exposed API key.

---

### Technical Specification:

-   **API Client (`api/client.ts`):**
    -   The `apiClient` function has been refactored to be path-aware for AI-related routes.
    -   It now checks if an incoming request path `startsWith('/api/ai/')`.
    -   If it's an AI-related request, it will make a real `fetch` call to the production `API_BASE_URL`.
    -   For all other non-migrated request paths, the request will continue to be routed to the internal `mockApiRouter`.

-   **Chat Service (`services/chatService.ts`):**
    -   This service has been completely refactored.
    -   The direct import and initialization of `@google/genai` has been removed.
    -   The `sendMessageStream` function has been rewritten to use the `apiClient` to make a `POST` request to a new `/api/ai/chat-stream` endpoint.
    -   The function now correctly handles a `ReadableStream` response from the backend, decoding the chunks and yielding them to the UI, preserving the real-time typing effect.

-   **Mock API (`api/mock.ts`):**
    -   A new handler for `POST /api/ai/chat-stream` has been implemented. This handler returns a `ReadableStream` that simulates the backend streaming AI-generated text chunks, allowing the new `chatService` to be tested with the mock server.

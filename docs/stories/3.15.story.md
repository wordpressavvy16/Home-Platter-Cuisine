# Story 3.15: AI-Powered Visual Search & Direct Meal Results

-   **Epic:** 3 (Customer Marketplace & Discovery Engine)
-   **Status:** Done

---

### User Story:
As a Customer, I want to upload a picture of a dish I'm craving, or use my camera to take one, and instantly see a list of specific, orderable meals from various kitchens that visually match it, so I can find and order exactly what I'm looking for with zero friction.

---

### Acceptance Criteria:

1.  **Given** a user is on the `HomePage` and clicks the "Image Search" camera icon.
2.  **When** they upload an image of a dish (e.g., pesto pasta), **Then** an AI service must be called to identify the name of the dish.
3.  **Given** the AI identifies the dish, **Then** the user must be navigated to a new, dedicated "Visual Search Results" page (`/visual-search`).
4.  **Given** the user is on the results page, **Then** it must display a grid of `MealCard` components showing all specific meals from all providers that match the identified dish name.
5.  **Given** the user is on the results page, **Then** they must be able to add any of the matching meals directly to their cart.
6.  **Given** a user attempts to use the camera for the search, **When** they click the "Use Camera" button, **Then** the browser's permission prompt must appear at that moment, not before.

---

### Technical Specification:

-   **Permissions (`metadata.json`):**
    -   The `requestFramePermissions` array has been cleared of the "camera" permission to prevent the app from asking on startup. The browser will now handle permission requests contextually.

-   **Routing (`App.tsx`):**
    -   A new route, `/visual-search`, has been added to the main router, which renders the new `VisualSearchResultsPage` component.

-   **AI Service (`services/geminiService.ts`):**
    -   The `generateMealIdeasFromImage` function has been replaced with a more specific `identifyDishFromImage(base64Image, mimeType, token): Promise<{ dishName: string }>`.
    -   This function calls a new backend endpoint: `POST /api/ai/identify-dish-from-image`.

-   **Mock API (`api/mock.ts`):**
    -   A new mock handler for `POST /api/ai/identify-dish-from-image` has been implemented. It simulates the AI analyzing an image and returns a hardcoded dish name (e.g., `{ "dishName": "Pesto Pasta" }`).

-   **Component Creation (`components/VisualSearchResultsPage.tsx`):**
    -   A new page component has been created to display the visual search results.
    -   It reads the search query (the dish name) from the URL's query parameters.
    -   It fetches all providers, then filters through every meal on the platform to find matches.
    -   It renders a grid of `MealCard` components for the matching meals.

-   **Component Refactoring:**
    -   **`components/ImageSearchModal.tsx`**: Has been updated to call the new `identifyDishFromImage` service and pass the resulting `dishName` to its `onComplete` callback.
    -   **`components/HomePage.tsx`**: The `handleImageSearchComplete` function has been updated to receive a `dishName` and navigate to the new `/visual-search` page with the name as a query parameter.


# Story 19.2: Provider Contextual CRM Actions

-   **Epic:** 19 (The Unified CRM Hub)
-   **Status:** Done

---

### User Story:
As a Provider, while viewing a customer's 360-degree profile, I want to perform contextual actions directly from that view (e.g., "Send Reward Coupon," "Send Review Reminder" next to an un-reviewed order), so that I can manage the customer relationship without navigating to different dashboard panels.

---

### Acceptance Criteria:

1.  **Given** a Provider is on the `CustomerProfilePage` (the 360-Degree View).
2.  **When** they view the main header of the page, **Then** the existing "Reward Customer" button must be present and functional, opening the `RewardCustomerModal` on click.
3.  **Given** the Provider selects the "Order History" tab.
4.  **When** they view the list of orders, **Then** a "Send Review Reminder" button must be visible next to *each* order where `reviewSubmitted` is `false`.
5.  **Given** an order has already been reviewed, **Then** the "Send Review Reminder" button must not be visible for that order.
6.  **Given** the Provider clicks the "Send Review Reminder" button, **Then** the button must be replaced by a "Reminder Sent" status, and the action must be triggered via an API call.

---

### Technical Specification:

-   **Component (`CustomerProfilePage.tsx`):**
    -   The component already contains the necessary state (`remindersSent`) and handler function (`handleSendReminder`) from a previous implementation (Story 7.1/7.4).
    -   The component also already includes the "Reward Customer" button and the logic to open the `RewardCustomerModal` (from Story 7.8).
    -   The primary change is to modify the JSX within the "Order History" tab.
    -   Inside the `customerOrders.map(...)` loop, add a new `div` for actions.
    -   Within this `div`, conditionally render the "Send Review Reminder" button based on `!order.reviewSubmitted` and whether the order ID is in the `remindersSent` set. This reuses the existing logic.
    -   The button will be a small, icon-based button for a clean UI, using the existing `BellIcon`.

-   **No New Components or API Changes:** This story builds upon existing functionality by simply adding a new UI element to trigger an existing action in a more contextual location. No new components, state management patterns, or API calls are required.

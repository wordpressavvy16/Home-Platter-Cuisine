
# Story 4.1: Implement Payment Gateway UI

-   **Epic:** 4 (Seamless Ordering & Transaction Flow)
-   **Status:** Done

---

### User Story:
As a Customer on the checkout page, I want to see and fill out a standard payment information form so that the checkout process feels complete, secure, and familiar.

---

### Acceptance Criteria:

1.  **Given** a user navigates to the `CheckoutPage`,
    **When** the page loads,
    **Then** they must see two distinct sections: "Shipping Information" and "Payment Information".

2.  **Given** the "Payment Information" section,
    **When** it is displayed,
    **Then** it must contain input fields for `Cardholder Name`, `Card Number`, `Expiration Date (MM/YY)`, and `CVV`.

3.  **Given** a user has not filled out all the required fields in both the shipping and payment forms,
    **When** they view the page,
    **Then** the "Place Order" button must be disabled.

4.  **Given** a user has filled out all required fields in both forms,
    **When** they view the page,
    **Then** the "Place Order" button must be enabled.

5.  **Given** a user clicks the "Place Order" button,
    **When** the order is submitted,
    **Then** the payment information is **NOT** sent to the backend; this is a UI-only implementation for now.

---

### Technical Specification:

-   **Component (`components/CheckoutPage.tsx`):**
    -   Introduce new `useState` hooks to manage the state for `cardNumber`, `cardName`, `expiryDate`, and `cvv`.
    -   Create a new card-styled `div` for the "Payment Information" section, visually separating it from the "Shipping Information".
    -   Inside this new section, add a form with labeled inputs for each of the payment fields, binding them to the new state variables.
    -   Update the `isFormValid` logic to include checks for the new payment fields. The button's `disabled` attribute should be tied to this logic.
    -   The `handleSubmit` function does **not** need to be changed to handle payment data. It will continue to submit only the user and cart information.

-   **Constants (`constants.tsx`):**
    -   Add a new `CreditCardIcon` SVG component to be used as a header icon for the "Payment Information" section to improve visual clarity.

---

# Story 7.8: Provider-Targeted Customer Rewards

-   **Epic:** 7 (Advanced CRM & Marketing Automation for Providers)
-   **Status:** Done

---

### User Story:
As a Provider, when viewing a specific customer's profile in my CRM, I want to be able to send them a special, personalized reward, such as a one-time discount coupon, to thank them for their loyalty or encourage them to order again.

---

### Acceptance Criteria:

1.  **Given** a Provider is on the `CustomerProfilePage` for a specific customer.
2.  **When** they view the page, **Then** a "Reward Customer" button must be visible.
3.  **Given** the Provider clicks the "Reward Customer" button, **Then** a modal must open, allowing them to configure a discount percentage and an expiration date for a new coupon.
4.  **Given** the Provider submits the reward form, **Then** a new, unique, single-use coupon must be created and associated with their provider account.
5.  **Given** the reward is created, **Then** a notification must be automatically sent to the targeted customer, informing them of the special offer and providing them with the unique coupon code.
6.  **Given** the targeted customer (or any other customer) tries to use this coupon code more than once, **Then** the validation must fail after the first successful use.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `Coupon` interface has been updated to include optional fields `isSingleUse?: boolean;` and `claimedByUserId?: string | null;` to track the usage of targeted rewards.

-   **API Service (`api/providerApi.ts`):**
    -   A new function, `createTargetedCoupon(providerId, couponData, token)`, has been created. It makes a `POST` request to `/api/providers/:providerId/targeted-coupon`.

-   **Mock API (`api/mock.ts`):**
    -   A new handler for `POST /api/providers/:id/targeted-coupon` has been implemented. It creates a new `Coupon` with `isSingleUse: true`, saves it to the provider's coupons, and generates a notification for the `targetUserId`.
    -   The `POST /api/orders/validate-coupon` handler has been updated to check the `isSingleUse` and `claimedByUserId` fields to prevent reuse.
    -   The `POST /api/orders/checkout` handler has been updated to find any applied single-use coupon and mark it as claimed by setting the `claimedByUserId`.

-   **Component Creation (`components/RewardCustomerModal.tsx`):**
    -   A new modal component has been created to provide the UI for configuring and submitting the targeted reward.

-   **Component Integration (`components/CustomerProfilePage.tsx`):**
    -   A "Reward Customer" button has been added, which opens the new `RewardCustomerModal`.
    -   The component now passes the necessary `onSubmit` handler to the modal to trigger the reward creation process.

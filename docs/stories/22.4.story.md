# Story 22.4: Enhance Information Scent & Trust Signals

-   **Epic:** 22 (Mobile-First Responsive UI/UX Overhaul)
-   **Status:** Done

---

### User Story:
As a Customer, I want to see clear, meaningful information at a glance (like delivery time, cost estimates, and safety badges) and have frictionless ways to filter content, so that I can make faster, more confident purchasing decisions, similar to the experience on leading apps like Zomato.

---

### Visual Specification:

This story mandates a comprehensive UI/UX refinement targeting the core discovery journey.

1.  **Systematic Iconography Audit:**
    *   **`HomePage.tsx`**: The "All Kitchens" title icon will be replaced with the `ShoppingBagIcon` for better marketplace representation. The icon-only view switcher buttons will have descriptive tooltips ("List View", "Map View") added for clarity on hover.
    *   **`MealProviderCard.tsx`**: The generic location icon will be replaced with the standard `LocationPinIcon`, and the ambiguous catering icon will be replaced with the `UsersIcon`.

2.  **Homepage Quick Filters:**
    *   A new, horizontally scrollable row of prominent, pill-shaped filter buttons will be added below the main search bar on the `HomePage`.
    *   Initial filters will include "Rating 4.5+", "Rating 4.0+", and "Veg Only".
    *   These buttons will directly apply the corresponding filter to the "All Kitchens" list, providing a one-tap filtering experience.

3.  **Enhanced `MealProviderCard`:**
    *   The card will be redesigned to be more information-dense.
    *   A new row will be added to display key decision-making information:
        *   **Average Cost (Simulated):** A simulated "Avg. Cost for two".
        *   **Delivery Time (Simulated):** A simulated "Est. Delivery Time".
        *   **Safety Badge (Simulated):** A new, hardcoded "Max Safety" badge with a shield icon to build immediate trust.

---

### Acceptance Criteria:

1.  **Given** the audit is complete, **Then** icons throughout the app are clear, consistent, and contextually appropriate.
2.  **Given** a user is on the `HomePage`, **Then** the new quick filter buttons are visible and correctly filter the list of providers.
3.  **Given** a user views a `MealProviderCard`, **Then** it now displays the new simulated information: average cost, delivery time, and safety badge.
4.  **Given** the changes are implemented, **Then** the application's discovery flow feels more professional and frictionless, aligning more closely with the Zomato reference.

---

### Technical Specification:

-   **Data Model (`types.ts`):** Add new optional fields to the `MealProvider` interface: `avgCostForTwo?: number;`, `deliveryTime?: string;`, and `hasMaxSafety?: boolean;`.
-   **Constants (`constants.tsx`):** Add a new `ClockIcon` for the delivery time display.
-   **Mock API (`api/mock.ts`):** Update the `MEAL_PROVIDERS_DEFAULT` data to include sample values for the new `MealProvider` fields.
-   **Component (`components/MealProviderCard.tsx`):** Redesign the card layout to incorporate the new data points and update the existing icons as specified.
-   **Component (`components/HomePage.tsx`):** Implement the new "Quick Filters" UI section and wire it up to the existing filter state handlers. Update the "All Kitchens" icon and add `title` attributes to the view switcher buttons.

# Story 12.2: Enhanced PWA Offline Experience with Data Caching

-   **Epic:** 12 (Platform Evolution)
-   **Status:** Done

---

### User Story:
As a user with an unreliable internet connection, I want the HomePlate app to feel fast and reliable by showing me content I've previously viewed, even when I'm offline, so that my browsing experience is not interrupted.

---

### Acceptance Criteria:

1.  **Given** a user is online and browses the `HomePage`, viewing several kitchen profiles.
2.  **When** the user then goes offline and reopens the app, **Then** they must see the list of kitchens they previously viewed, instead of an error page.
3.  **Given** the user is offline, **When** they view the app, **Then** a clear, non-intrusive banner must appear at the top of the screen indicating they are offline (e.g., "You are offline. Showing cached content.").
4.  **Given** the user's network connection is restored, **Then** the offline banner must disappear automatically.
5.  **Given** the caching is active, **Then** the application should feel faster on subsequent visits because it loads cached data first before fetching fresh data in the background (Stale-While-Revalidate).

---

### Technical Specification:

-   **Service Worker (`sw.js`):**
    -   The `fetch` event listener has been completely refactored.
    -   It now distinguishes between API requests (e.g., to `/api/*`) and other asset requests.
    -   For **API requests**, it implements a **"stale-while-revalidate"** strategy:
        1.  It responds with the cached version of the data immediately if available.
        2.  It then sends the network request in the background.
        3.  If the network request is successful, it updates the cache with the fresh data for the next time.
    -   A new cache, `homeplate-data-v1`, has been created to store dynamic API responses separately from the static app shell.

-   **Hook Creation (`hooks/useOnlineStatus.ts`):**
    -   A new, reusable React hook has been created to abstract the logic for detecting the browser's online/offline status.
    -   It uses the `navigator.onLine` property and adds `online` and `offline` event listeners to the `window` object.

-   **Component Creation (`components/OfflineBanner.tsx`):**
    -   A new, simple component has been created to display the offline status banner.

-   **Component Integration (`App.tsx`):**
    -   The main `App` component now uses the `useOnlineStatus` hook.
    -   It conditionally renders the `OfflineBanner` component at the top of the layout when the user is offline.

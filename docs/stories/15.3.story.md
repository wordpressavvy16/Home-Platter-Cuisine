# Story 15.3: Implement Super Admin Order Dispute Resolution System

-   **Epic:** 15 (Platform Governance & Trust Tools)
-   **Status:** Done

---

### User Story:
As a Super Admin, I need a dedicated system to review and mediate customer-reported issues with specific orders (e.g., "wrong item," "quality issue"), so that I can resolve disputes fairly, process refunds or credits, and maintain a high level of customer trust.

---

### Acceptance Criteria:

1.  **Given** a Customer is viewing their order history on the `ProfilePage`.
2.  **When** an order has the status 'DELIVERED', **Then** a "Report an Issue" button must be visible.
3.  **Given** the Customer clicks "Report an Issue", **Then** a modal must open, allowing them to select a reason and describe the problem.
4.  **Given** the Customer submits the issue, **Then** the order must be marked as "disputed", and the "Report an Issue" button should be disabled for that order.
5.  **Given** a Super Admin is on their `SuperAdminDashboard`, **Then** a new "Order Dispute Resolution" panel must be visible.
6.  **Given** the dispute panel is visible, **Then** it must display a list of all orders with an open dispute, showing customer/provider details, the order items, and the customer's complaint.
7.  **Given** the admin views a dispute, **Then** a "Mark as Resolved" button must be available. Clicking it should resolve the dispute and remove it from the queue.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   New types `DisputeReason` and `OrderDispute` have been created.
    -   The `Order` interface has been updated with an optional `dispute?: OrderDispute;` field.

-   **API Layer:**
    -   **`api/orderApi.ts`**: A new function, `reportIssueOnOrder(orderId, reason, message, token)`, has been added to allow customers to create a dispute.
    -   **`api/adminApi.ts`**:
        -   A new function, `getOpenDisputes(token)`, calls `GET /api/admin/disputes/open`.
        -   A new function, `resolveDispute(orderId, token)`, calls `PUT /api/admin/disputes/:orderId/resolve`.

-   **Mock API (`api/mock.ts`):**
    -   Handlers for the new API endpoints have been implemented to create disputes, fetch open disputes, and resolve them by updating the `dispute.status` on the order object.

-   **Component Creation:**
    -   `components/ReportIssueModal.tsx`: A new modal for customers to submit their order issue.
    -   `components/DisputeResolutionPanel.tsx`: A new panel for the Super Admin dashboard to manage open disputes.

-   **Component Refactoring:**
    -   **`components/ProfilePage.tsx`**: The `OrderHistoryCard` now includes the "Report an Issue" button and the logic to open the `ReportIssueModal`.
    -   **`components/SuperAdminDashboard.tsx`**: The new `DisputeResolutionPanel` has been added to the layout.

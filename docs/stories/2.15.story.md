# Story 2.15: Intelligent New Order Alert System

-   **Epic:** 2 (Provider Storefront & Product Management)
-   **Status:** Done

---

### User Story:
As a Provider in a busy environment, I need an unmissable alert for new orders that includes a loud, persistent sound, so that I can acknowledge incoming orders immediately and avoid missing them. The alert should respect my working hours and provide a clear way to be dismissed.

---

### Acceptance Criteria:

1.  **Given** a provider has their dashboard open and is within their defined working hours.
2.  **When** a new order with `status: 'PENDING'` is received, **Then** an audible alarm must start playing in a loop, and a full-screen "New Order Received!" modal must appear.
3.  **Given** the alert is active, **Then** the modal must display key order details and a prominent "Acknowledge & Mute Alarm" button.
4.  **Given** the provider clicks the "Acknowledge" button, **Then** the alarm sound must stop immediately, and the modal must close.
5.  **Given** the provider does not acknowledge the alert, **Then** the sound must automatically stop after a set duration (e.g., 45-60 seconds) to avoid being a nuisance.
6.  **Given** the provider misses the initial audible alert, **Then** the new order in their `OrdersPanel` must have a persistent, silent visual indicator (e.g., a pulsing border) until it is interacted with.
7.  **Given** the provider's kitchen is closed (either via master toggle or schedule), **Then** the audible alarm and modal must not be triggered, but the pulsing visual indicator should still appear.

---

### Technical Specification:

-   **Component (`components/OrdersPanel.tsx`):**
    -   The component's `useEffect` hook for fetching orders has been enhanced to include new order detection logic. It now compares the list of new `PENDING` orders against the list from the previous fetch.
    -   When a new order is detected, it checks the provider's availability using the existing `getKitchenStatus` logic.
    -   If the kitchen is open, it sets a new state `newOrderForAlert`, which triggers the modal and sound.
    -   If the kitchen is closed, it sets the `pulsingOrderId` state directly.
    -   The `IncomingOrderCard` now accepts an `isPulsing` prop to apply the `animate-pulse-border` CSS class.

-   **Component Creation (`components/NewOrderAlertModal.tsx`):**
    -   A new modal component has been created to display the high-priority alert.
    -   It uses `ReactDOM.createPortal` to render into the modal root.
    -   It does not manage its own state but receives the `order` and an `onAcknowledge` callback.

-   **Audio Management:**
    -   A new audio file, `public/alarm.mp3`, has been added.
    -   The `OrdersPanel` uses the browser's `Audio` API to play the alarm sound in a loop. It manages the audio instance in a `useRef` to control play/pause.
    -   A `setTimeout` is used to automatically stop the alarm, and `clearTimeout` is used in the cleanup function and `onAcknowledge` handler.

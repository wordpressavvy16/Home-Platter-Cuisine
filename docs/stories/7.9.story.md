# Story 7.9: Implement Automated New Customer Onboarding Workflow

-   **Epic:** 7 (Advanced CRM & Marketing Automation for Providers)
-   **Status:** Done
-   **Proposed In:** PRD v3.0

---

### User Story:
As a Provider, I want new customers who place their first order with me to automatically receive a welcoming notification and a special discount for their next purchase, so that they feel valued, are encouraged to become repeat customers, and my customer retention improves without any manual effort.

---

### Acceptance Criteria:

1.  **Given** a Customer is placing an order.
2.  **When** the `checkout` process is finalized, **Then** the system must check if this is the customer's very first order with that specific provider.
3.  **Given** it is their first order with that provider, **Then** two automated actions must be triggered:
    a. A new, single-use `Coupon` (e.g., 10% off) must be created, associated with the provider, and made available to that customer.
    b. A new `Notification` must be sent to the customer, welcoming them and informing them about their new discount coupon.
4.  **Given** it is *not* their first order with that provider, **Then** no special coupon or welcome notification should be generated.
5.  **Given** the customer receives the welcome coupon, **When** they try to use it, **Then** it must function as a standard single-use coupon, only valid for that specific provider.

---

### Technical Specification:

-   **API Layer (`api/mock.ts`):**
    -   The mock handler for `POST /api/orders/checkout` will be enhanced.
    -   Inside the loop that processes the cart for each provider, a new check will be added: `const isFirstOrderForProvider = !db.orders.some(o => o.userId === user.id && o.providerId === providerId);`.
    -   If this check is `true`, the handler will:
        1.  Create a new `Coupon` object. This coupon will have `isSingleUse: true`, a generated code (e.g., `WELCOME[USERNAME]`), and a set expiration (e.g., 30 days).
        2.  Add this new coupon to the specific provider's `coupons` array in the mock database.
        3.  Create a new `Notification` object for the customer (`userId`) informing them of their reward.
        4.  Add this new notification to the global `db.notifications` array.

-   **No UI Changes:**
    -   This is a backend logic enhancement. No changes are required in the UI components. The existing notification system will display the new notification, and the existing coupon system will allow the customer to use the new code at checkout.

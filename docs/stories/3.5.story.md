# Story 3.5: Favorite Kitchens for Customers

-   **Epic:** 3 (Customer Marketplace & Discovery Engine)
-   **Status:** Done

---

### User Story:
As a Customer, I want to be able to "favorite" a kitchen, so that I can easily find and re-order from my preferred providers in the future.

---

### Acceptance Criteria:

1.  **Given** a logged-in Customer is viewing a kitchen's card on the `HomePage`,
    **When** they view the card,
    **Then** a "favorite" icon (e.g., a heart) must be visible on the card.

2.  **Given** a logged-in Customer is on a `MealProviderDetails` page,
    **When** they view the page header,
    **Then** a "favorite" icon must be visible near the kitchen's name.

3.  **Given** a Customer clicks the favorite icon to add a kitchen to their favorites,
    **When** the action is completed,
    **Then** the icon's appearance must change to a "filled" or "active" state, and the provider's ID must be saved to the user's profile.

4.  **Given** a Customer clicks the favorite icon to remove a kitchen from their favorites,
    **When** the action is completed,
    **Then** the icon must revert to its default state, and the provider's ID must be removed from the user's profile.

5.  **Given** a Customer is on their `ProfilePage`,
    **When** they view the page,
    **Then** a new section or tab titled "My Favorite Kitchens" must be visible, displaying a list of all their favorited providers.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `User` interface has been updated to include an optional array of strings: `favoriteProviderIds?: string[];`.

-   **API Service (`api/userApi.ts`):**
    -   A new function `updateUserFavorites(userId: string, favoriteProviderIds: string[], token: string): Promise<User>` has been created.
    -   This makes a `PUT` request to a new endpoint `/api/users/:userId/favorites`.

-   **Mock API (`api/mock.ts`):**
    -   The `User` objects in the mock DB have been updated to include an empty `favoriteProviderIds: []` array by default.
    -   A handler for `PUT /api/users/:id/favorites` has been implemented to update the `favoriteProviderIds` array.

-   **UI Components:**
    -   **`MealProviderCard.tsx` & `MealProviderDetails.tsx`**:
        -   These components now receive `favoriteProviderIds` and authentication status.
        -   A heart icon button has been added, which calls a function to add/remove the provider ID and then calls the `updateUserFavorites` API.
    -   **`ProfilePage.tsx`**:
        -   A new "My Favorite Kitchens" section filters and displays `MealProviderCard` components for providers whose IDs are in the `user.favoriteProviderIds` array.

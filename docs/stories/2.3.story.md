# Story 2.3: Provider Order Fulfillment Management

-   **Epic:** 2 (Provider Storefront & Product Management)
-   **Status:** Done

---

### User Story:
As a Provider, I want to manage the status of my incoming orders (e.g., Confirm, Mark as Preparing, Mark as Delivered), so that I can track my operational workflow and keep my customers informed.

---

### Acceptance Criteria:

1.  **Given** an `Order` is created,
    **When** it is first received by a provider,
    **Then** its default status must be 'PENDING'.

2.  **Given** a Provider is viewing their `OrdersPanel` on the `DashboardPage`,
    **When** they see an order,
    **Then** the order's current status (e.g., 'PENDING', 'CONFIRMED', 'PREPARING') must be clearly displayed.

3.  **Given** a Provider sees a 'PENDING' order in their `OrdersPanel`,
    **When** they view the order card,
    **Then** an "Accept" and "Cancel" button must be visible.

4.  **Given** a Provider clicks the "Accept" button on a 'PENDING' order,
    **When** the action is completed,
    **Then** the order's status must change to 'CONFIRMED', and the action button should change to "Mark as Preparing".

5.  **Given** a Provider clicks "Mark as Preparing" on a 'CONFIRMED' order,
    **When** the action is completed,
    **Then** the order's status must change to 'PREPARING', and the action button should change to "Mark as Out for Delivery".

6.  **Given** a Provider clicks "Mark as Out for Delivery" on a 'PREPARING' order,
    **When** the action is completed,
    **Then** the order's status must change to 'OUT_FOR_DELIVERY', and the action button should change to "Mark as Delivered".

7.  **Given** a Provider clicks "Mark as Delivered" on an 'OUT_FOR_DELIVERY' order,
    **When** the action is completed,
    **Then** the order's status must change to 'DELIVERED', and no further action buttons should be visible.

8.  **Given** a Customer is viewing their order history on their `ProfilePage`,
    **When** a provider updates the status of their order,
    **Then** the customer must see the updated status in a user-friendly format.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `Order` interface's `status` field has been updated to support a granular lifecycle: `status: 'PENDING' | 'CONFIRMED' | 'PREPARING' | 'OUT_FOR_DELIVERY' | 'DELIVERED' | 'CANCELLED';`.

-   **API Service (`api/orderApi.ts`):**
    -   The existing function `updateOrderStatus(orderId: string, status: Order['status'], token: string): Promise<Order>` is used to handle all status transitions.
    -   It makes a `PUT` request to the endpoint: `/api/orders/:orderId/status`.

-   **Mock API (`api/mock.ts`):**
    -   The `/api/orders/checkout` endpoint ensures all newly created orders have a default `status: 'PENDING'`.
    -   The handler for `PUT /api/orders/:id/status` finds the specified order in the mock database and updates its `status` field.
    -   This endpoint also generates a `Notification` for the customer for each status change.

-   **Provider UI (`components/OrdersPanel.tsx`):**
    -   The `IncomingOrderCard` component displays the current order status prominently.
    -   It uses conditional logic to render the correct action button(s) based on the current `order.status`.
    -   The `onClick` handlers for these buttons call the `updateOrderStatus` API function.

-   **Customer UI (`components/ProfilePage.tsx`):**
    -   The `OrderHistoryCard` component displays the order's `status` in a user-friendly way using the `statusStyles` object.

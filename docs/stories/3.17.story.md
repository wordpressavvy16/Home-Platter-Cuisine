
# Story 3.17: Voice-Activated Search

-   **Epic:** 3 (Customer Marketplace & Discovery Engine)
-   **Status:** Done

---

### User Story:
As a Customer on the homepage, I want to use my voice to search for meals, so that I can find what I'm looking for hands-free and more conveniently, especially when I'm multitasking.

---

### Acceptance Criteria:

1.  A microphone icon is visible in the main search bar on the `HomePage`.
2.  Clicking the microphone icon prompts the user for microphone permission if not already granted.
3.  When the application is listening, the UI provides clear visual feedback (e.g., a pulsing icon, "Listening..." placeholder text).
4.  The user's speech is converted to text and populates the search input field.
5.  After the speech is transcribed, the search is automatically triggered using the resulting text.
6.  The feature uses the browser's native Web Speech API (`SpeechRecognition`).
7.  If a browser does not support the Web Speech API, the microphone icon is not rendered.

---

### Technical Specification:

-   **Permissions (`metadata.json`):**
    -   The `"microphone"` permission must be added to the `requestFramePermissions` array to enable access to the device's microphone.

-   **Component (`components/HomePage.tsx`):**
    -   Add new state variables to manage the listening state (`isListening`) and any potential speech recognition errors.
    -   Use a `useEffect` hook to check for browser support (`window.SpeechRecognition` or `window.webkitSpeechRecognition`). The microphone icon button should only be rendered if support is detected.
    -   Implement a `handleVoiceSearch` function that:
        -   Initializes an instance of the `SpeechRecognition` object.
        -   Sets up event handlers for `onresult`, `onerror`, and `onend`.
        -   Calls `recognition.start()` to begin listening.
    -   The `onresult` handler will extract the final transcript from the event, update the main `searchTerm` state, and then programmatically call the existing `performSearch` function.
    -   The `onend` handler will set `isListening` back to `false`.
    -   The search bar's JSX will be updated to include the new microphone button and conditionally change its appearance (e.g., icon style, input placeholder) based on the `isListening` state.

-   **Constants (`constants.tsx`):**
    -   A new `MicrophoneIcon` SVG component will be created for the search bar button.

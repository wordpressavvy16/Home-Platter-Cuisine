# Story 23.1: Frontend - Connect to Live Order Service

-   **Epic:** 23 (Live Backend - Order & Transaction Migration)
-   **Status:** Done

---

### User Story:
As a Frontend Developer, I need to update the application to communicate with the new live Order Service for all order-related operations, so that the platform can process real, persistent transactions instead of using the mock API.

---

### Acceptance Criteria:

1.  The application's API calls for all order-related actions (checkout, fetching orders, updating status, etc.) are now directed to the live backend endpoint (`https://api.homeplatter.com`) instead of the internal mock server.
2.  All other API calls (for AI features, support tickets, etc.) must continue to function by routing to the mock server to prevent breaking other parts of the application.
3.  The `api/client.ts` "switch" logic is updated to selectively route all order-related requests based on their paths.
4.  All components that rely on order data (`CheckoutPage.tsx`, `ProfilePage.tsx`, `OrdersPanel.tsx`, etc.) work seamlessly with the data from the live backend.
5.  The application correctly handles both successful and unsuccessful responses from the live Order Service.

---

### Technical Specification:

-   **API Client (`api/client.ts`):**
    -   The `apiClient` function will be refactored to be path-aware for order-related routes.
    -   It will now check if an incoming request path matches patterns like `/api/orders/*`, `/api/subscriptions/*`, `/api/customers/*`, etc.
    -   If it's an order-related request, it will make a real `fetch` call to the production `API_BASE_URL`.
    -   For all other non-auth/provider request paths, the request will continue to be routed to the internal `mockApiRouter`.
    -   This continues the phased migration strategy, allowing services to be switched over one by one.

-   **No other code changes are required.** The existing `orderApi.ts` and UI components already use the `apiClient`, so they will inherit this new routing behavior automatically.

---

### Definition of Done (DoD):
-   [x] Code implemented as per the technical specification.
-   [x] The `api/client.ts` now selectively routes order and transaction requests to the live backend.
-   [x] The rest of the application remains functional by continuing to use the mock API for non-migrated services.
-   [x] The application's core transactional pages now make real network requests for order data.
-   [x] Story status updated to 'Done' in `changelog.md` and the Epic 23 PRD file.

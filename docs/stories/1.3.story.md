
# Story 1.3: User Notification Center

-   **Epic:** 1 (Unified User & Onboarding System)
-   **Status:** Done

---

### User Story:
As a user (either a Customer or a Provider), I want to receive notifications for important events, so that I am always aware of timely updates related to my orders and account.

---

### Acceptance Criteria:

1.  **Given** a user is logged in,
    **When** they view the main `Header`,
    **Then** a bell icon must be visible. If there are unread notifications, it should display a count badge.

2.  **Given** the user clicks the bell icon,
    **When** the action is performed,
    **Then** a dropdown panel must appear, listing their recent notifications, with the newest at the top.

3.  **Given** a Provider receives a new order,
    **When** the system processes it,
    **Then** a notification must be generated for that provider (e.g., "You have a new order from [Customer Name]!").

4.  **Given** a Customer's order status is changed by a provider (e.g., to 'CONFIRMED' or 'DELIVERED'),
    **When** the status is updated,
    **Then** a notification must be generated for that customer (e.g., "Your order from [Provider Name] has been confirmed!").

5.  **Given** a Provider receives a new review,
    **When** the review is submitted,
    **Then** a notification must be generated for that provider (e.g., "[Customer Name] left you a [5]-star review!").

6.  **Given** a user opens the notification panel,
    **Then** the unread notification count should be cleared (marked as read).

---

### Technical Specification:

-   **Component Creation (`components/NotificationPanel.tsx`):**
    -   Create a new component to render the notification dropdown. It will receive a list of notifications as props and display them.

-   **Header Integration (`components/Header.tsx`):**
    -   Add a new state to manage the visibility of the notification panel.
    -   Fetch the user's notifications when the component mounts.
    -   Render a bell icon button. The button will show a count of unread notifications and toggle the `NotificationPanel`.
    -   When the panel is opened, call an API function to mark notifications as read.

-   **API Service (`api/userApi.ts` - New File):**
    -   Create a new API service file for user-centric actions.
    -   `getNotifications(token: string): Promise<Notification[]>` -> `GET /api/users/me/notifications`
    -   `markNotificationsAsRead(token: string): Promise<void>` -> `POST /api/users/me/notifications/read`

-   **Mock API (`api/mock.ts`):**
    -   Add a new `db.notifications` array to the mock database.
    -   Implement handlers for the new `GET` and `POST` notification endpoints.
    -   **Crucially, modify existing endpoints** (`POST /api/orders/checkout`, `PUT /api/orders/:id/status`, `POST /api/providers/:id/reviews`) to *generate and add new notification objects* to the `db.notifications` table when those actions occur. This simulates the event-driven nature of a real system.

-   **Type Definition (`types.ts`):**
    -   Add a new interface to support the feature:
        ```typescript
        export interface Notification {
          id: string;
          userId: string;
          message: string;
          timestamp: string;
          isRead: boolean;
          linkTo?: {
            route: Route;
            params?: Record<string, string>;
          };
        }
        ```

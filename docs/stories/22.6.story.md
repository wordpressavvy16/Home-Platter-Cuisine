# Story 22.6: Implement a Scalable, Form-Based Partner Inquiry System

-   **Epic:** 22 (Mobile-First Responsive UI/UX Overhaul)
-   **Status:** Done

---

### User Story:
As a potential partner (e.g., a delivery service or ingredient supplier), I want to find a clear way to contact Home Platter on the "Partner with us" page, so that I can inquire about business opportunities beyond just being a kitchen. As a platform owner, I want a scalable way to handle these different types of inquiries.

---

### Visual & Technical Specification:

1.  **Refactor the "Partner with us" Page:**
    *   The existing Markdown page (`content/pages/partner-with-us.md`) will be enhanced.
    *   A new section titled **"Other Partnership Opportunities"** will be added.
    *   This section will contain a special placeholder tag: `{{FORM:PARTNER_INQUIRY}}`.

2.  **Create a Partner Inquiry Form Component (`components/forms/PartnerInquiryForm.tsx`):**
    *   A new, reusable form component will be created.
    *   It will be a simple, client-side form with fields for:
        *   Full Name
        *   Business/Company Name
        *   Type of Partnership (a dropdown with options like "Delivery Partner," "Ingredient Supplier," "Other")
        *   Email Address
        *   A brief message.
    *   Upon submission, the form will not make an API call but will simply display an inline "Thank You" message to simulate a successful inquiry.

3.  **Enhance the Static Page Renderer (`components/pages/StaticPageRenderer.tsx`):**
    *   The `parseMarkdown` function within the renderer will be upgraded.
    *   It will be able to recognize the `{{FORM:PARTNER_INQUIRY}}` tag within the Markdown content.
    *   When it encounters this tag, it will dynamically render the `PartnerInquiryForm.tsx` component in its place. This creates a scalable pattern for embedding interactive components within static content pages.

---

### Acceptance Criteria:

1.  **Given** a user navigates to the `/partner-with-us` page.
2.  **When** the page loads, **Then** it must display both the existing "Become a Kitchen Partner" section and a new "Other Partnership Opportunities" section.
3.  **Given** the "Other Partnership Opportunities" section is visible, **Then** it must contain a functional inquiry form.
4.  **Given** a user fills out and submits the inquiry form, **Then** they must see a "Thank You" confirmation message.
5.  **Given** the implementation, **Then** the `StaticPageRenderer` must be capable of dynamically injecting components based on tags in the Markdown source.

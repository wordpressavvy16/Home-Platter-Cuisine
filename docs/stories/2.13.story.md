# Story 2.13 (Revised): Provider Availability & Advanced Scheduling

-   **Epic:** 2 (Provider Storefront & Product Management)
-   **Status:** Done

---

### User Story:
As a Provider, I want to set my kitchen's daily operating hours, including separate service windows for lunch and dinner with pre-order cut-off times, so that I can manage my cooking schedule effectively. I also need a master switch to close my shop instantly for emergencies.

---

### Acceptance Criteria:

1.  **Given** a Provider is on their `DashboardPage`, **Then** a master "Accepting Orders" toggle must be visible in their profile panel and be functional, immediately opening or closing their storefront.

2.  **Given** a Provider is on the `EditProfilePage`, **Then** a new "Weekly Schedule" section must allow them to add, edit, and remove service windows for each day of the week (e.g., "Monday Lunch: Serving 1-3 PM, Order by 11:30 AM").

3.  **Given** a Customer views a provider's page when the master toggle is OFF or it's outside of any defined service hours, **Then** a "Currently Closed" message must be displayed, and all "Add to Cart" buttons must be disabled.

4.  **Given** a Customer views the page within a valid ordering window (before the cut-off time), **Then** they must see a message indicating the deadline (e.g., "Order for lunch by 11:30 AM") and be able to add items to their cart.

5.  **Given** a Customer views the page after a cut-off time but before the next window opens, **Then** they must see a message informing them when the next ordering window is available, and ordering must be disabled.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   Create a new `ServiceWindow` interface: `{ mealType: string; servingStartTime: string; servingEndTime: string; orderCutoffTime: string; }`.
    -   Update the `MealProvider` interface to include: `isAcceptingOrders?: boolean;` and `weeklySchedule?: { [day: string]: ServiceWindow[] };`.

-   **Component (`components/MyKitchenProfilePanel.tsx`):**
    -   Add a stateful toggle switch for "Accepting Orders".
    -   This component will now use the `useAuth` hook to get the `token` and `refreshProviderProfile` function.
    -   The toggle's `onChange` handler will call `providerApi.updateProviderProfile` to save the new `isAcceptingOrders` state.

-   **Component (`components/EditProfilePage.tsx`):**
    -   Add a comprehensive UI section for managing the `weeklySchedule`.
    -   This section will allow providers to add, remove, and edit service windows for each day of the week using time inputs.
    -   The main `handleSubmit` function will save the entire `weeklySchedule` object.

-   **Component (`components/MealProviderDetails.tsx`):**
    -   Implement business logic (likely in a `useMemo` hook) to determine the kitchen's current operational status based on the master toggle, the weekly schedule, and the current time.
    -   Render a prominent status banner based on the result of this logic.
    -   Pass a new boolean prop, `isKitchenOpen`, to all `MealCard` components.

-   **Component (`components/MealCard.tsx`):**
    -   Accept the new `isKitchenOpen` prop.
    -   Modify the "Add" button's disabled logic to be `disabled={!isAvailable || !isKitchenOpen}`.

-   **Mock API (`api/mock.ts`):**
    -   Update the default provider data to include `isAcceptingOrders: true` and a sample `weeklySchedule`.
    -   Ensure the `PUT /api/providers/:id` endpoint correctly saves the new scheduling fields.

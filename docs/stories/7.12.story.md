# Story 7.12: Implement Automated Customer Re-engagement Workflow

-   **Epic:** 7 (Advanced CRM & Marketing Automation for Providers)
-   **Status:** Done
-   **Proposed In:** PRD v3.0

---

### User Story:
As a Provider, I want the platform to automatically identify my customers who haven't ordered in a while (e.g., 30 days) and send them a special "we miss you" offer, so that I can proactively win back their business and reduce customer churn without manual effort.

---

### Acceptance Criteria:

1.  **Given** a logged-in user opens the application.
2.  **When** the application loads, **Then** it must automatically check for any providers they have previously ordered from but not in the last 30 days.
3.  **Given** such a "lapsed" relationship is found, **Then** a `Notification` must be automatically sent to that user, offering them a special discount for that specific provider.
4.  **Given** a notification is sent, **Then** a new, single-use `Coupon` (e.g., 15% off) must be created for that user and provider.
5.  **Given** the user receives the notification, **Then** it must contain a message like "We miss you! Here's a 15% discount for your next order from [Provider Name]." and link to the provider's page.
6.  **Given** a re-engagement notification has been sent for a specific provider, **Then** the system must not send another one for a significant period (e.g., 90 days) to avoid spamming.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `User` interface will be updated to include an optional field: `reEngagementStatus?: { [providerId: string]: string };` to store the timestamp of the last re-engagement notification sent for each provider.

-   **Application Logic (`App.tsx`):**
    -   A new `useEffect` hook will be added to run on application load for authenticated users.
    -   This effect will fetch the user's profile and full order history.
    -   It will identify unique providers the user has ordered from.
    -   For each provider, it will find the most recent order date.
    -   It will check if the last order was more than 30 days ago AND if a re-engagement notification hasn't been sent in the last 90 days (by checking the new `reEngagementStatus` object).
    -   If conditions are met, it will call a new API function to trigger the re-engagement reward.

-   **API Layer:**
    -   **`api/userApi.ts`**: A new function `sendReEngagementReward(providerId: string, token: string)` will be created.
    -   **`api/mock.ts`**:
        -   A new handler for `POST /api/users/me/re-engagement-reward` will be implemented.
        -   This handler will:
            1.  Find the current user and the specified provider.
            2.  Update the user's `reEngagementStatus` for that provider with the current timestamp.
            3.  Create a new, single-use `Coupon` with a special discount (e.g., 15%) and add it to the provider's coupons.
            4.  Create a new `Notification` for the user with the offer and a deep link to the provider's page.


# Story 7.11: Implement Automated Review Request Sequence

-   **Epic:** 7 (Advanced CRM & Marketing Automation for Providers)
-   **Status:** Done
-   **Proposed In:** PRD v3.0

---

### User Story:
As a Provider, I want the platform to automatically send a review request to a customer a set amount of time after their order is delivered, so that I can consistently gather feedback and build my kitchen's reputation without manual effort.

---

### Acceptance Criteria:

1.  **Given** a logged-in user opens the application.
2.  **When** the application loads, **Then** it must automatically check for any of their orders that were delivered more than 24 hours ago and have not yet been reviewed.
3.  **Given** such an order is found, **Then** a `Notification` must be automatically sent to that user, prompting them to leave a review.
4.  **Given** the user receives this notification, **Then** clicking on it must deep-link them directly to their profile page with the review submission form automatically opened for that specific order.
5.  **Given** a reminder has been sent for a specific order, **Then** the system must not send another reminder for that same order to avoid spamming the user.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `Order` interface will be updated to include an optional boolean field: `reviewReminderSent?: boolean;`.

-   **Application Logic (`App.tsx`):**
    -   A new `useEffect` hook will be added to run on application load for authenticated users.
    -   This effect will fetch the user's orders (`orderApi.getOrdersForUser`).
    -   It will filter for orders that are `DELIVERED`, older than 24 hours, `!reviewSubmitted`, and `!reviewReminderSent`.
    -   For each eligible order, it will call a new API function to trigger the reminder notification.

-   **API Layer:**
    -   **`api/orderApi.ts`**: A new function `sendAutomatedReviewReminder(orderId: string, token: string)` will be created.
    -   **`api/mock.ts`**:
        -   A new handler for `POST /api/orders/:orderId/automated-review-reminder` will be implemented.
        -   This handler will find the order in the mock DB, set its `reviewReminderSent` flag to `true`, and create a new `Notification` for the customer.
        -   Crucially, the `linkTo` property of the notification will be structured to facilitate deep linking: `{ path: '/profile', params: { openReviewForOrderId: order.id } }`.

-   **UI Component (`components/ProfilePage.tsx`):**
    -   A new `useEffect` hook will be added to check the `routeParams` for `openReviewForOrderId`.
    -   If the parameter is present and the `orders` have loaded, it will find the corresponding order and call the existing `handleOpenReviewModal` function, passing in that order.

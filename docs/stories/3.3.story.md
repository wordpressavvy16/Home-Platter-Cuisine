# Story 3.3: Unified AI Search (Text & Image)

-   **Epic:** 3 (Customer Marketplace & Discovery Engine)
-   **Status:** Done

---

### User Story:
As a Customer, I want a single, powerful search bar on the homepage that allows me to search with either text or an image, so that I have a unified and intuitive way to discover meals.

---

### Acceptance Criteria:

1.  **Given** a user is on the `HomePage`,
    **When** they view the main search area,
    **Then** the text input field must now be accompanied by an icon button (e.g., a camera icon) for initiating an image search.

2.  **Given** the user clicks the "Image Search" icon button,
    **When** the action is performed,
    **Then** a modal must open, containing the UI for either uploading a file or using the device's camera.

3.  **Given** the user provides an image and the AI analysis is complete,
    **When** the meal ideas are generated,
    **Then** the modal should close, and the primary text search bar on the `HomePage` should be populated with the top AI-generated suggestion.

4.  **Given** the search bar has been populated with the AI suggestion,
    **When** the user sees this,
    **Then** the search should be automatically triggered to filter the list of providers.

5.  **Given** this new unified search component is implemented,
    **When** the `HomePage` is rendered,
    **Then** the separate `MealIdeaGenerator` panel must be completely removed.

---

### Technical Specification:

-   **Component Refactoring (`components/HomePage.tsx`):**
    -   The separate `<MealIdeaGenerator />` component instance has been removed from the main render block.
    -   The main search `<form>` has been updated to include a new icon button next to the "Search" button.
    -   A new state, `isImageSearchModalOpen`, controls the visibility of the image search modal.

-   **Component Creation (`components/ImageSearchModal.tsx` - New):**
    -   The new component, `ImageSearchModal`, is responsible for the image search UI.
    -   The logic and UI from the old `MealIdeaGenerator.tsx` component have been moved into this modal.
    -   The modal accepts an `onComplete(searchTerm: string)` callback function as a prop.
    -   After the Gemini API returns meal ideas, the modal calls `onComplete()` with the first idea and then closes.

-   **Integration Logic (`components/HomePage.tsx`):**
    -   The `HomePage` renders `<ImageSearchModal />` conditionally.
    -   It passes a `handleImageSearchComplete` function to the modal's `onComplete` prop, which sets the `searchTerm` state, triggers the provider filtering logic, and closes the modal.
    -   The `MealIdeaGenerator.tsx` file has been deleted.

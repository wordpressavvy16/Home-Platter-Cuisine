# Story 4.3: Quick Re-order from Profile Page

-   **Epic:** 4 (Seamless Ordering & Transaction Flow)
-   **Status:** Done

---

### User Story:
As a returning Customer, I want to see a list of my previously ordered items on my profile page and be able to quickly add them to my cart again with a single click, so that I don't have to search for my favorite meals every time I visit.

---

### Acceptance Criteria:

1.  **Given** a Customer is on their `ProfilePage`,
    **When** they view the page,
    **Then** a new tab or section titled "My Regulars" or "Previously Ordered" must be visible.

2.  **Given** the "My Regulars" section is viewed,
    **When** the data is loaded,
    **Then** it must display a unique list of individual meal items the customer has ordered in the past, sorted by how recently they were ordered.

3.  **Given** an item is displayed in this list,
    **When** a customer views it,
    **Then** it must be presented in a compact card format showing the meal's image, name, the kitchen it's from, and an "Add to Cart" button.

4.  **Given** a customer clicks the "Add to Cart" button on a "regular" item,
    **When** the action is performed,
    **Then** the item must be added to their shopping cart.

5.  **Given** a previously ordered item is no longer available (e.g., marked as 'Unavailable' or deleted by the provider),
    **When** the customer views their "My Regulars" list,
    **Then** the item's "Add to Cart" button must be disabled.

---

### Technical Specification:

-   **Component (`components/ProfilePage.tsx`):**
    -   Add a new state to manage the active tab, including a new "My Regulars" option.
    -   Create a `useMemo` hook to derive the list of unique, previously ordered items from the user's `orders` history. This should flatten all items from all orders and then create a unique set.
    -   For each item in the "My Regulars" list, implement logic to check its current availability. This requires finding the original `Meal` object in the corresponding `MealProvider`'s current menu.
    -   The availability check must also account for the provider's current open/closed status, reusing the logic from `MealProviderDetails.tsx`.
    -   The "Add to Cart" button's `disabled` attribute will be controlled by this availability logic.
    -   The `onClick` handler for the "Add to Cart" button will use the `addToCart` function from the `useCart` hook.

-   **No API or Data Model Changes:** This is a frontend-only enhancement. All necessary data is already available from existing API calls on the `ProfilePage`.

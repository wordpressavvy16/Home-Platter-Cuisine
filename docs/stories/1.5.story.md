# Story 1.5: Enhanced Form Usability with Placeholders and Inline Validation

-   **Epic:** 1 (Unified User & Onboarding System)
-   **Status:** Done

---

### User Story:
As a user interacting with any form in the application, I want to see helpful placeholder text that guides my input and receive immediate, clear feedback if I make a mistake, so that the process of filling out forms is easy, intuitive, and error-free.

---

### Acceptance Criteria:

1.  **Given** a user is on any page with a form (e.g., `AuthPage`, `CheckoutPage`).
2.  **When** they view an empty input field, **Then** it must display an animated "typing" placeholder that cycles through examples of valid input (e.g., typing out "your.name@email.com").
3.  **Given** a user focuses on an input field, **Then** the typing animation must stop, allowing the user to enter their data.
4.  **Given** a user enters invalid data into a required field (e.g., an incorrectly formatted email) and then clicks or tabs away.
5.  **When** the field loses focus, **Then** the input's border must turn red, and a specific, helpful error message must appear directly below that field (e.g., "Please enter a valid email address").
6.  **Given** a user enters valid data into a field, **When** the input becomes valid, **Then** the input's border must turn green, a success icon (e.g., a checkmark) should appear, and any previous error message must be hidden.
7.  **Given** a user tries to submit a form with errors, **Then** the main submission button must be disabled, and all fields with errors should remain highlighted.

---

### Technical Specification:

-   **Cross-Cutting Concern:** This is a comprehensive UI/UX improvement that will touch multiple form-based components.
-   **Hook Creation (`hooks/useTypingPlaceholder.ts`):**
    -   A new reusable React hook will be created to manage the logic for the animated typing placeholder.
    -   It will accept an array of strings (phrases) and return the current animated string to be used in the input's `placeholder` attribute.
    -   The animation logic will be contained entirely within this hook.
-   **Component Refactoring (All Forms):**
    -   All form components (`AuthPage.tsx`, `CheckoutPage.tsx`, `AddressFormModal.tsx`, etc.) will be updated.
    -   They will implement more robust state management to track for each field: its value, whether it has been "touched" (blurred), and its validation status (`valid`, `invalid`, or `pristine`).
    -   Input elements will be enhanced with conditional classes to apply different border colors (e.g., `border-red-500` for invalid, `border-green-500` for valid).
    -   They will conditionally render error messages and success/error icons next to the input fields based on the validation state.
    -   Each component will use the new `useTypingPlaceholder` hook to provide animated examples for key input fields.
-   **Validation Logic:**
    -   Client-side validation functions will be implemented for common checks (e.g., required field, valid email format, minimum password length, credit card number format).

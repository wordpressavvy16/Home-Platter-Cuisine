# Story 15.4: Implement Super Admin Customer Compensation Tools

-   **Epic:** 15 (Platform Governance & Trust Tools)
-   **Status:** Done

---

### User Story:
As a Super Admin, after resolving a dispute in favor of a customer, I need the ability to issue a platform-funded compensation (like a special, single-use coupon) directly to that customer, so that I can ensure customer satisfaction and rectify negative experiences, even if the provider is unresponsive or at fault.

---

### Acceptance Criteria:

1.  **Given** a Super Admin is viewing an open dispute in the `DisputeResolutionPanel`.
2.  **When** they view the actions, **Then** a "Resolve & Compensate" button must be visible alongside the standard resolution button.
3.  **Given** the admin clicks "Resolve & Compensate", **Then** a new modal (`CompensationModal`) must open.
4.  **Given** the `CompensationModal` is open, **Then** it must allow the admin to specify a discount percentage and an expiration date for a compensation coupon.
5.  **Given** the admin submits the compensation form, **Then** a new, unique, single-use coupon must be created, marked as "platform-funded", and linked to the dispute.
6.  **Given** the coupon is created, **Then** a notification must be sent to the customer informing them of their compensation coupon.
7.  **Given** the compensation is sent, **Then** the original dispute must be marked as 'RESOLVED' and removed from the active queue.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `Coupon` interface will be updated to include `fundedBy?: 'PLATFORM' | 'PROVIDER';` and `linkedDisputeId?: string;`.

-   **API Layer:**
    -   **`api/adminApi.ts`**: A new function, `issueCompensationCoupon(data, token)`, will be created to call `POST /api/admin/compensate`.
    -   **`api/mock.ts`**:
        -   A new handler for `POST /api/admin/compensate` will be implemented. It will create a new `Coupon` object with `isSingleUse: true` and `fundedBy: 'PLATFORM'`, save it to a global or dummy provider's coupon list, and generate a notification for the customer.

-   **Component Creation (`components/CompensationModal.tsx`):**
    -   A new modal component will be created for the Super Admin to configure and send the compensation coupon.

-   **Component Refactoring (`components/DisputeResolutionPanel.tsx`):**
    -   The panel will be updated to include the "Resolve & Compensate" button.
    -   State will be added to manage the `CompensationModal`.
    -   The `onConfirm` handler for the compensation modal will chain two API calls: first `issueCompensationCoupon`, and then `resolveDispute`.

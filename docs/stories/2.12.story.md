# Story 2.12 (Revised): Advanced Meal Management (Visibility, Availability & Deletion)

-   **Epic:** 2 (Provider Storefront & Product Management)
-   **Status:** Done

---

### User Story:
As a Provider, I want to granular control over my menu items, including the ability to temporarily hide them (for seasonal items), mark them as out of stock (for daily inventory), and permanently delete them, so that I can efficiently manage my menu without re-creating items unnecessarily.

---

### Acceptance Criteria:

1.  **Given** a Provider is on the `ManageMenuPage`, **Then** each `ManageableMealCard` must have:
    *   A primary toggle for **"Visible"**.
    *   A secondary toggle for **"In Stock"** (enabled only when visible).
    *   A "Remove" button for permanent deletion.

2.  **Given** a Provider toggles a meal's **"Visibility"** to OFF, **Then** the meal must NOT appear on the customer-facing `MealProviderDetails` page.

3.  **Given** a meal is "Visible" and a Provider toggles its **"Availability"** to OFF, **Then** the meal must appear on the customer's menu with an "Out of Stock" badge and a disabled "Add" button.

4.  **Given** a Provider clicks the "Remove" button, **Then** they must be shown a confirmation dialog before the meal is permanently deleted from their menu.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   Update the `Meal` interface to include two new optional boolean fields: `isVisible?: boolean;` and `isAvailable?: boolean;`. A meal with `undefined` for these fields will be treated as visible and available by default for backward compatibility.

-   **Component (`components/ManageableMealCard.tsx`):**
    -   Add two toggle switches for "Visible" and "In Stock". The "In Stock" toggle will be disabled if the "Visible" toggle is off.
    -   The `onRemove` button's `onClick` handler will be wrapped in a `window.confirm()` dialog to prevent accidental deletion.
    -   The component will receive a new `onUpdate` prop to communicate status changes back to the parent page.

-   **Component (`components/ManageMenuPage.tsx`):**
    -   A new `handleMealUpdate` function will be created to handle changes from the toggles. It will call the `providerApi.updateMeal` service with the full, updated meal object.
    -   This new handler will be passed down to the `ManageableMealCard` component.

-   **Component (`components/MealProviderDetails.tsx`):**
    -   The `useMemo` hook that groups the menu will be updated to first filter the menu list, removing any meal where `meal.isVisible` is `false`.

-   **Component (`components/MealCard.tsx`):**
    -   The customer-facing meal card will be updated to check `meal.isAvailable`. If it is `false`, it will render an "Out of Stock" badge and disable the "Add" button.

-   **Mock API (`api/mock.ts`):**
    -   The default meal data will be updated to include `isVisible: true` and `isAvailable: true` for all items.
    -   The `PUT /api/providers/:id/menu/:mealId` endpoint will correctly handle updates to these new boolean fields.

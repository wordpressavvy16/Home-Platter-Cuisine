# Story 7.4: Activate Real Notifications for Review Reminders

-   **Epic:** 7 (Advanced CRM & Marketing Automation for Providers)
-   **Status:** Done

---

### User Story:
As a Provider, when I click the "Send Review Reminder" button for a customer's order, I want the system to generate a real notification that the customer will receive, so that my reminder is effective and integrated with the platform's notification system.

---

### Acceptance Criteria:

1.  **Given** a Provider is on the `CustomerProfilePage`,
    **When** they click the "Send Review Reminder" button for an un-reviewed order,
    **Then** an API call must be made to a backend endpoint to trigger a notification.

2.  **Given** the backend processes the reminder request,
    **When** the action is successful,
    **Then** a new `Notification` object must be created in the database for the customer associated with that order.

3.  **Given** the customer logs in or is already logged in after the reminder is sent,
    **When** they check their notifications,
    **Then** they must see a new notification with a message like "A friendly reminder to review your recent order from [Provider Name]."

4.  **Given** the provider clicks the reminder button,
    **When** the API call is in progress,
    **Then** the button should show a loading or disabled state.

5.  **Given** the API call is successful,
    **When** the provider views the button,
    **Then** it should optimistically update to show a "Reminder Sent" status.

---

### Technical Specification:

-   **Component (`components/CustomerProfilePage.tsx`):**
    -   The `handleSendReminder` function has been converted to an `async` function.
    -   It now calls a new API service function: `providerApi.sendReviewReminder(orderId, token)`.
    -   The existing `remindersSent` local state is kept for optimistic UI updates.
    -   Error handling has been added to alert the provider if the reminder fails.

-   **API Service (`api/providerApi.ts`):**
    -   A new function has been created: `sendReviewReminder(orderId: string, token: string): Promise<void>`.
    -   This function makes a `POST` request to a new backend endpoint: `/api/reminders/review`.

-   **Mock API (`api/mock.ts`):**
    -   A new mock handler for `POST /api/reminders/review` has been implemented.
    -   This handler finds the corresponding order, finds the provider's name, constructs a new `Notification` object with a deep link to the profile page, and pushes it into the `db.notifications` array for the correct `userId`.

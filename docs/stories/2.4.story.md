
# Story 2.4: Dashboard At-a-Glance Profile Summary

-   **Epic:** 2 (Provider Storefront & Product Management)
-   **Status:** Done

---

### User Story:
As a Provider, when I view my main dashboard, I want to see a summary card for my kitchen that shows my current average rating and total number of reviews, so that I can instantly assess my public reputation without navigating to other pages.

---

### Acceptance Criteria:

1.  **Given** a Provider is on their `DashboardPage`,
    **When** they view the page,
    **Then** the "My Kitchen Profile" panel must be replaced with a more informative summary panel.

2.  **Given** the new profile summary panel is displayed,
    **When** the provider data has loaded,
    **Then** the panel must clearly display the provider's current average rating (e.g., "4.8 / 5.0").

3.  **Given** the new profile summary panel is displayed,
    **When** the provider data has loaded,
    **Then** the panel must also display the total number of reviews the provider has received.

4.  **Given** the new profile summary panel is displayed,
    **When** the provider clicks on it,
    **Then** they must still be navigated to the full "Edit Profile" page (`DASHBOARD_PROFILE_EDIT`).

---

### Technical Specification:

-   **Component (`components/MyKitchenProfilePanel.tsx`):**
    -   This component has been refactored from a simple link to a dynamic summary card.
    -   It accepts the full `provider: MealProvider` object as a prop from `DashboardPage`.
    -   It is responsible for displaying the `provider.name`, `provider.rating`, and `provider.reviews.length`.
    -   It uses icons and clear typography for a visually appealing summary.
    -   The entire component is wrapped in a clickable element that navigates the user to the `DASHBOARD_PROFILE_EDIT` route.

-   **Component (`components/DashboardPage.tsx`):**
    -   The `MyKitchenProfilePanel` is passed the full `provider` object.
    -   The panel is rendered directly, with navigation logic handled internally by the panel itself.

-   **No API or Data Model Changes:** This is a UI-enhancement story and requires no changes to the backend API, data services, or `types.ts`.

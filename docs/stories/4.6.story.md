# Story 4.6: Real-Time Order Tracking Map

-   **Epic:** 4 (Seamless Ordering & Transaction Flow)
-   **Status:** Done

---

### User Story:
As a Customer, after my order is dispatched, I want to see a real-time map that tracks my food's journey from the kitchen to my doorstep, so that I feel informed and confident about my delivery.

---

### Acceptance Criteria:

1.  **Given** a Customer is viewing their order history on the `ProfilePage`.
2.  **When** an order has the status 'OUT_FOR_DELIVERY', **Then** a "Track Order" button must be visible on that order card.
3.  **Given** the Customer clicks the "Track Order" button, **Then** they must be navigated to a new, dedicated order tracking page (e.g., `/#/track-order/:orderId`).
4.  **Given** the tracking page is loaded, **Then** it must display a map-like interface showing the provider's location (start point), the customer's location (end point), and the delivery route.
5.  **Given** the tracking page is active, **Then** it must periodically fetch updates and show a moving icon (e.g., a truck) that animates along the delivery route to represent the order's real-time progress.
6.  **Given** the order status changes (e.g., to 'DELIVERED'), **Then** the tracking page should update to reflect the final status.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   A new `OrderTracking` interface has been created to hold tracking data.
    -   The `Order` interface has been updated to include an optional `tracking?: OrderTracking;` field.

-   **Component Creation:**
    -   `components/OrderTrackingPage.tsx`: A new page component that fetches the order and provider data, manages polling for updates, and renders the map and order details.
    -   `components/OrderTrackingMap.tsx`: A new component that visualizes the map, provider/customer locations, route, and the moving delivery icon.

-   **API Service (`api/orderApi.ts`):**
    -   A new function, `getOrderById(orderId, token)`, has been created to fetch the details of a single, specific order.

-   **Mock API (`api/mock.ts`):**
    -   The handler for `PUT /api/orders/:id/status` has been enhanced. When an order's status is set to `OUT_FOR_DELIVERY`, it now generates and attaches simulated `tracking` data to the order object, including a start time and a path.
    -   A new handler for `GET /api/orders/:id` has been implemented. If the requested order is out for delivery, this handler calculates the `currentLocation` of the delivery based on the elapsed time since the `startTime`, simulating real-time progress.

-   **Component Integration:**
    -   **`App.tsx`**: A new route `/track-order/:orderId` has been added to the main router.
    -   **`ProfilePage.tsx`**: The `OrderHistoryCard` now conditionally renders a "Track Order" button that navigates to the new tracking page.

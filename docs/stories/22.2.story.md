# Story 22.2: Responsive Overhaul for the Meal Provider Details Page

-   **Epic:** 22 (Mobile-First Responsive UI/UX Overhaul)
-   **Status:** Done

---

### User Story:
As a user on a mobile device, when I view a kitchen's detail page, I want the layout to be fully responsive and optimized for my small screen, so that I can easily read information, browse the menu, and make purchasing decisions without horizontal scrolling or layout issues.

---

### Visual Specification:

1.  **Banner & Header Section:**
    *   On mobile, the main banner image will have a reduced height (`h-56 sm:h-64`).
    *   The provider's name, chef name, and action buttons (Share, Follow) will stack vertically below the banner image, rather than being overlaid on top of it, to ensure maximum readability.

2.  **Main Info Panel:**
    *   The panel containing the kitchen's long description and rating will take the full width of the screen on mobile.
    *   The rating badge will move below the description text on small screens to maintain a clean vertical flow.

3.  **Sticky Category Navigation:**
    *   The category navigation bar will become a horizontally scrollable element on mobile (`overflow-x-auto whitespace-nowrap`).
    *   This prevents the links from wrapping into multiple lines and breaking the layout, while still providing access to all categories. The bar will remain sticky to the top of the viewport below the header.

4.  **Menu & Meal Cards:**
    *   The two-column grid for meal cards (`grid-cols-1 md:grid-cols-2`) will collapse into a single column on mobile screens. Each `MealCard` will take the full width.
    *   The `MealCard` itself will be made responsive: the layout will switch from a horizontal `md:flex-row` on larger screens to a stacked, vertical `flex-col` on mobile.

5.  **All Other Sections:**
    *   All subsequent sections (Tiffin Plans, Catering, Reviews, etc.) will naturally stack into a single, easy-to-scroll column on mobile devices.

---

### Acceptance Criteria:

1.  **Given** a user is on a `MealProviderDetails` page on a small screen (mobile).
2.  **When** the page renders, **Then** all content must fit within the viewport width without requiring horizontal scrolling.
3.  **Given** the user is on mobile, **Then** the menu grid must collapse to a single column.
4.  **Given** the user is on mobile, **Then** the category navigation bar must be horizontally scrollable.
5.  **Given** the user is on a large screen (desktop/tablet), **Then** the existing two-column layout must be preserved.

---

### Technical Specification:

-   **Component (`components/MealProviderDetails.tsx`):**
    -   Apply responsive Tailwind CSS classes (`sm:`, `md:`, `lg:`) to adjust layouts for the banner, info panel, and menu grid sections based on the visual specification.
    -   Specifically, change `grid-cols-2` to `grid-cols-1 md:grid-cols-2`.
    -   Modify the category navigation bar `div` to include `overflow-x-auto whitespace-nowrap` and ensure it works with the existing `sticky` positioning.

-   **Component (`components/MealCard.tsx`):**
    -   Refactor the main container `div` to be responsive. Change `flex-row` to `flex-col md:flex-row`.
    -   Adjust the image container's width for mobile vs. desktop (e.g., `w-full md:w-32`).

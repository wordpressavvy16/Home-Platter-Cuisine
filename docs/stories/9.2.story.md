# Story 9.2: Super Admin Provider Management

-   **Epic:** 9 (Platform Administration & Multitenancy)
-   **Status:** Done

---

### User Story:
As a Super Administrator, I want to view a list of all providers on the platform and manage their account status, so that I can maintain the quality and security of the marketplace.

---

### Acceptance Criteria:

1.  **Given** a Super Admin is on the `SuperAdminDashboard`,
    **When** the page loads,
    **Then** a "Provider Management" panel must be visible, displaying a table of all providers.

2.  **Given** the provider table is displayed,
    **When** the admin views a row,
    **Then** it must show the Provider's Name, Chef Name, Join Date, and current Status (e.g., Active, Pending Setup, Suspended).

3.  **Given** a provider has not completed their profile (`isSetupComplete: false`),
    **When** the admin views their row,
    **Then** an "Approve" button must be visible. Clicking it should set `isSetupComplete: true`.

4.  **Given** a provider is active and not suspended,
    **When** the admin views their row,
    **Then** a "Suspend" button must be visible. Clicking it should set `isSuspended: true`.

5.  **Given** a provider is suspended (`isSuspended: true`),
    **When** the admin views their row,
    **Then** a "Reactivate" button must be visible. Clicking it should set `isSuspended: false`.

6.  **Given** a provider is suspended,
    **When** they attempt to log in,
    **Then** they must be shown an error message and be denied access.

7.  **Given** a provider is suspended,
    **When** a customer views the `HomePage`,
    **Then** the suspended provider must not appear in the list of available kitchens.

---

### Technical Specification:

-   **Component Creation (`components/ProviderManagementPanel.tsx`):**
    -   Create a new, self-contained component `ProviderManagementPanel` to handle all logic and UI for this feature.
    -   It will use a `useEffect` hook to fetch all providers from a new admin-specific API endpoint.
    -   It will render a table displaying the provider data.
    -   It will contain handler functions (`handleStatusChange`) that call the appropriate API functions to update a provider's status. The UI should update optimistically and then revert on API failure.

-   **API Service (`api/adminApi.ts` - New File):**
    -   Create a new API service file dedicated to administrative functions.
    -   `getAllProviders(token)`: Calls `GET /api/admin/providers`.
    -   `approveProvider(providerId, token)`: Calls `PUT /api/admin/providers/:id/approve`.
    -   `suspendProvider(providerId, token)`: Calls `PUT /api/admin/providers/:id/suspend`.
    -   `reactivateProvider(providerId, token)`: Calls `PUT /api/admin/providers/:id/reactivate`.

-   **Mock API (`api/mock.ts`):**
    -   Add handlers for all the new admin endpoints listed above. These handlers will modify the `db.providers` array in the mock database.
    -   The `GET /api/providers` (public) endpoint must be updated to filter out any provider where `isSuspended: true`.
    -   The `POST /api/v1/auth/login` endpoint must be updated to reject logins from users whose provider profile is suspended.

-   **Data Model (`types.ts`):**
    -   Update the `MealProvider` interface to include `joinDate: string;` and `isSuspended?: boolean;`.

-   **Component Integration (`components/SuperAdminDashboard.tsx`):**
    -   Import and render the new `ProviderManagementPanel` component within the dashboard layout.

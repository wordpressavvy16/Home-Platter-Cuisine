# Story 12.3: Enable PWA Push Notifications

-   **Epic:** 12 (Platform Evolution)
-   **Status:** Done

---

### User Story:
As a user who has installed the HomePlate app, I want to receive push notifications for important events (like order updates or new messages) directly on my device, even when the app is closed, so that I can stay informed in real-time.

---

### Acceptance Criteria:

1.  **Given** a user is on their `ProfilePage`, **Then** a new "Notification Settings" section must be visible.
2.  **Given** the user has not yet granted permission, **When** they view the settings, **Then** an "Enable Notifications" button must be displayed.
3.  **Given** the user clicks "Enable Notifications", **When** the action is performed, **Then** the browser's native permission prompt must appear.
4.  **Given** the user grants permission, **When** they view the settings panel, **Then** it must show a confirmation message (e.g., "Notifications are enabled!") and a button to "Send a Test Notification".
5.  **Given** the user clicks "Send a Test Notification", **Then** a native push notification from "HomePlate" must appear on their device.
6.  **Given** an order's status changes, **When** the mock API processes this, **Then** it must log a message to the console simulating that a push notification would have been sent to a real push service.

---

### Technical Specification:

-   **Component Creation (`components/NotificationSettingsPanel.tsx`):**
    -   A new component has been created to encapsulate all UI and logic for managing push notification permissions.
    -   It uses `Notification.permission` to check the current status and `Notification.requestPermission()` to prompt the user.
    -   It includes a button that sends a message to the service worker to trigger the display of a test notification.

-   **Component Integration (`components/ProfilePage.tsx`):**
    -   A new "Notifications" tab has been added to the profile page's navigation.
    -   The new `NotificationSettingsPanel` is rendered when this tab is active.

-   **Service Worker (`sw.js`):**
    -   The service worker has been enhanced with three new event listeners:
        -   `push`: Listens for actual push events from a push service. For now, this is for future compatibility. It contains the logic to display a received notification.
        -   `notificationclick`: Handles the user clicking on a notification, focusing or opening the app window.
        -   `message`: Listens for internal messages from the client-side app, specifically to handle the "SHOW_TEST_NOTIFICATION" command from the new settings panel.

-   **Mock API (`api/mock.ts`):**
    -   The handlers for events that should trigger a push notification (e.g., `PUT /api/orders/:id/status`, `POST /api/orders/:id/request-delivery`) have been updated.
    -   They now include a `console.log` statement with a `[PUSH SIM]` prefix, simulating the backend's action of sending a push message to a service like Firebase Cloud Messaging.

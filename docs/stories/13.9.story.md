# Story 13.9: Refactor and Stabilize Global Error Boundary

-   **Epic:** 13 (Pre-Launch Polish & Optimization)
-   **Status:** Done

---

### User Story:
As a Developer, I want to refactor the `ErrorBoundary` component to use modern React patterns and resolve existing type errors, so that the application is more stable, maintainable, and less prone to critical crashes.

---

### Acceptance Criteria:

1.  The `ErrorBoundary` component no longer uses a `constructor` to initialize state.
2.  The component uses the class property syntax for state initialization (e.g., `state = { hasError: false };`).
3.  The application compiles without any TypeScript errors related to the `ErrorBoundary` component.
4.  The Error Boundary continues to function correctly, catching and displaying a fallback UI for runtime errors in its children.

---

### Technical Specification:

-   **Component (`components/ErrorBoundary.tsx`):**
    -   Remove the `constructor(props)` method.
    -   Initialize the `state` directly as a class property: `state: State = { hasError: false };`.
    -   This resolves a common issue with TypeScript's handling of `this` in class constructors.
    -   The `getDerivedStateFromError` and `componentDidCatch` methods remain unchanged.

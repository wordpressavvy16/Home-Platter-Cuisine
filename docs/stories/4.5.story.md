# Story 4.5: Customer Meal Wishlist

-   **Epic:** 4 (Seamless Ordering & Transaction Flow)
-   **Status:** Done

---

### User Story:
As a Customer, I want to save individual meals to a "wishlist," so that I can easily keep track of dishes I'm interested in trying later without having to remember which kitchen they belong to.

---

### Acceptance Criteria:

1.  **Given** a logged-in Customer is viewing a `MealCard` on a provider's detail page.
2.  **When** they view the card, **Then** a "wishlist" icon (e.g., a heart) must be visible.
3.  **Given** a Customer clicks the wishlist icon, **Then** the icon's state must toggle (e.g., filled/unfilled), and the meal's ID must be added to or removed from their user profile.
4.  **Given** a Customer is on their `ProfilePage`, **Then** a new "My Wishlist" tab must be available.
5.  **Given** the Customer views the "My Wishlist" tab, **Then** it must display a list of all their wishlisted meals, each with an image, name, the kitchen it's from, and a button to "Add to Cart" or "Remove from Wishlist".

---

### Technical Specification:

-   **Data Model (`types.ts`):** The `User` interface will be updated to include an optional `wishlistMealIds?: string[];`.
-   **API Layer:**
    -   **`api/userApi.ts`**: A new function `updateUserWishlist` will be created to save the user's wishlist.
    -   **`api/mock.ts`**: The `User` object will be updated, and a new handler for the wishlist endpoint will be added.
-   **UI Components:**
    -   **`MealCard.tsx`**: Will be updated to display a heart icon that toggles the meal's wishlist status.
    -   **`ProfilePage.tsx`**: A new "My Wishlist" tab will be added to display the wishlisted items.
-   **State Management (`AuthProvider.tsx`):**
    -   The `fullUser` state (fetched via `userApi.getUserProfile`) will be used to manage and display the wishlist across the application.

# Story 13.14: Final UI/UX Polish (Phase 2)

-   **Epic:** 13 (Pre-Launch Polish & Optimization)
-   **Status:** Done

---

### User Story:
As a Developer, I need to address a final set of user-reported UI/UX flaws to ensure the application is polished and professional, focusing on icon layout, navigation consistency, and message clarity.

---

### Acceptance Criteria:

1.  **[UI Flaw - Meal Card Icons]** The action icons (wishlist/collection) on the `MealCard` must be permanently fixed to prevent any possibility of overlapping with the discount badge by moving them to a different, more robustly positioned location.
2.  **[UX Flaw - Back Button]** The back arrow on the `MealProviderDetails` page must have consistent and predictable behavior. It should always navigate the user back to the homepage (`/`) instead of relying on browser history, which can be unreliable.
3.  **[UX Flaw - Status Message]** The kitchen status message on the `MealProviderDetails` page must be more intelligent and context-aware. If the lunch window is closed but dinner is still available on the same day, it must state this clearly (e.g., "Orders for Lunch are now closed. You can pre-order for Dinner!") instead of a generic "Today's orders are closed" message.

---

### Technical Specification:

-   **Meal Card UI (`components/MealCard.tsx`):**
    -   The card header has been redesigned. The `h3` element for the title and the `div` for the action icons are now wrapped in a flex container (`flex items-center gap-2`). This places the icons inline with the title, physically separating them from the top-right corner where the discount badge resides.

-   **Back Button Logic (`components/ProviderDetailsPage.tsx`):**
    -   The `onBack` handler, which was previously passed down, has been simplified. The `onClick` event on the back button now directly calls `navigate('/')`, ensuring it always returns the user to the homepage. The `window.history.back()` call has been removed.

-   **Status Message Logic (`components/MealProviderDetails.tsx`):**
    -   The `getKitchenAvailability` function has been enhanced.
    -   It now includes logic to find the name of the most recently closed service window on the current day.
    -   The message generation logic has been updated to use this information. If a `lastMissedWindowName` is found and the `nextAvailableSlot` is on the same day, it constructs the more informative and context-aware message.

---

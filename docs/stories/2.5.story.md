# Story 2.5: Provider-Initiated Order Cancellation

-   **Epic:** 2 (Provider Storefront & Product Management)
-   **Status:** Done

---

### User Story:
As a Provider, if I am unable to fulfill an incoming order due to an unexpected issue (e.g., out of stock), I want to be able to cancel the order from my dashboard so that I can maintain accurate operational status and the customer is notified.

---

### Acceptance Criteria:

1.  **Given** a Provider is viewing a 'PENDING' order in their `OrdersPanel`,
    **When** they view the order card,
    **Then** a "Cancel" button must be visible next to the "Accept" button.

2.  **Given** a Provider clicks the "Cancel" button,
    **When** the action is completed,
    **Then** the order's status must be updated to 'CANCELLED'.

3.  **Given** an order's status is 'CANCELLED',
    **When** the Provider views the order card,
    **Then** all action buttons (Accept, Cancel) must be hidden, and a "Cancelled" status indicator should be shown.

4.  **Given** an order's status is 'CONFIRMED',
    **When** the Provider views the order card,
    **Then** the "Cancel" button must no longer be visible.

5.  **Given** a Customer is viewing their order history on their `ProfilePage`,
    **When** a provider cancels their order,
    **Then** the customer must see the updated 'CANCELLED' status for that order.

---

### Technical Specification:

-   **API (`api/orderApi.ts`, `api/mock.ts`):**
    -   The existing `updateOrderStatus` function and the `PUT /api/orders/:orderId/status` mock endpoint already support the 'CANCELLED' status. No changes are required in the API layer.

-   **Provider UI (`components/OrdersPanel.tsx`):**
    -   In the `IncomingOrderCard` component, a "Cancel" button is rendered conditionally, only if `order.status === 'PENDING'`.
    -   The `onClick` handler for this button calls the `onUpdateStatus(order.id, 'CANCELLED')` function.
    -   A `window.confirm()` dialog is used to prevent accidental clicks.

-   **UI State (`components/OrdersPanel.tsx`):**
    -   Conditional logic ensures that once an order's status is 'DELIVERED' or 'CANCELLED', no action buttons are rendered, only a final status indicator.

-   **Customer UI (`components/ProfilePage.tsx`):**
    -   The `statusStyles` object already contains styling for the 'CANCELLED' state. The existing logic automatically displays the new status correctly.

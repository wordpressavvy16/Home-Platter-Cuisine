# Story 22.5: Final UI Polish & User Journey Refinement

-   **Epic:** 22 (Mobile-First Responsive UI/UX Overhaul)
-   **Status:** Done

---

### User Story:
As a user and project owner, I want the application to have a final layer of professional polish, with consistent design, functional user journeys, and scalable layouts, to ensure a high-quality experience for both customers and providers.

---

### Acceptance Criteria:

1.  **[Footer Symmetry]** The App Store and Google Play download buttons in the footer must be perfectly symmetrical and aligned.
2.  **[Footer Functionality - FAQs]** The "FAQs for Customers" and "FAQs for Providers" links in the footer must be functional and open the AI Support Chatbot when clicked.
3.  **[Footer Functionality - Partner]** The "Partner with us" link in the footer must navigate to the `AuthPage` and automatically pre-select the "Kitchen Owner" role on the sign-up form.
4.  **[Layout Scalability]** All homepage sections containing provider cards (e.g., "Top Rated", "All Kitchens") must be refactored from wrapping grids into horizontally scrolling carousels to be more scalable and modern.
5.  **[Card Consistency]** The `MealProviderCard` must be refactored to remove inconsistent internal dividers for a cleaner, more professional appearance.

---

### Future Considerations:

*   **Provider Approval Workflow:** The current "Partner with us" flow directly creates a provider account. A more robust, production-ready solution requires a Super Admin approval step. This will be addressed in a new, dedicated epic.

---

### Technical Specification:

-   **Global State (`providers/ChatbotProvider.tsx`):**
    -   Create a new `ChatbotProvider` and `useChatbot` hook to manage the global state of the AI chatbot's visibility. This allows the footer to programmatically open the chatbot.

-   **Component (`components/Footer.tsx`):**
    -   Apply consistent height and width classes to the App Store/Google Play `img` tags.
    -   Use the new `useChatbot` hook to call `openChatbot` on the FAQ links.
    -   Update the "Partner with us" button to call `navigate('/auth', { mode: 'signup', role: 'PROVIDER' })`.

-   **Component (`components/AuthPage.tsx`):**
    -   Update the component to read the `role` from `routeParams` and use it to set the initial state of the role selector on the sign-up form.

-   **Component (`components/ProviderCarousel.tsx` & `HomePage.tsx`):**
    -   Refactor the layout from a CSS grid to a `flex overflow-x-auto` container to create a true horizontal carousel.
    -   Apply this refactored carousel pattern to all provider collections on the `HomePage`, including the main "All Kitchens" list.

-   **Component (`components/MealProviderCard.tsx`):**
    -   Remove the `h-full` class to allow for natural height in the new flexbox carousel.
    -   Remove the `border-y` class from the info row and standardize on a single `border-t` for the final section to clean up the internal layout.

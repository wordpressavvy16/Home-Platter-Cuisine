# Story 16.3: Security - Implement Multi-Factor Authentication (MFA/OTP)

-   **Epic:** 16 (Live Backend - Authentication & Security Foundation)
-   **Status:** Done

---

### User Story:
As a User, I want to secure my account by enabling Multi-Factor Authentication (MFA) using a One-Time Password (OTP) from an authenticator app (like Google Authenticator), so that my account is protected even if my password is compromised.

---

### Acceptance Criteria:

1.  A new "Security" section is available in the user's `ProfilePage`.
2.  Within this section, users can initiate the MFA setup process, which displays a QR code to be scanned with an authenticator app.
3.  The user must verify the setup by entering a valid, time-based one-time password (TOTP) from their app.
4.  Once MFA is enabled, the `AuthPage` login flow is updated to require both a password and a valid OTP code in a two-step process.
5.  Users have an option to disable MFA from their profile page after successfully authenticating.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `User` interface has been updated to include `mfaEnabled?: boolean;` and `mfaSecret?: string;`.

-   **API Layer:**
    -   **`api/authApi.ts`**: New functions `setupMfa`, `verifyMfa`, `disableMfa`, and `verifyLoginMfa` have been added. The main `login` function now throws a custom `MfaRequiredError` to trigger the two-step flow.
    -   **`api/mock.ts`**: Handlers for all new MFA endpoints have been implemented. The `/login` handler now returns a special response if MFA is enabled for the user.

-   **Component Creation:**
    -   `components/SecuritySettingsPanel.tsx`: A new panel for the `ProfilePage` to manage enabling/disabling MFA.
    -   `components/MfaSetupModal.tsx`: A new modal to guide the user through scanning a QR code and verifying their authenticator app.

-   **Component Refactoring:**
    -   **`components/ProfilePage.tsx`**: A new "Security" tab has been added to render the `SecuritySettingsPanel`.
    -   **`components/AuthPage.tsx`**: The component's state machine has been significantly updated to handle a new `mfa_challenge` mode. It now catches the `MfaRequiredError` and displays a form for the user to enter their OTP to complete the login.
    -   **`providers/AuthProvider.tsx`**: A new `verifyLoginWithMfa` function has been added to handle the second step of the login process.


# Story 1.1: Core User Authentication

-   **Epic:** 1 (Unified User & Onboarding System)
-   **Status:** Done

---

### User Story:
As a new user (either a Customer or a Provider), I want to sign up for an account, and as a returning user, I want to log in, so that I can access the platform's features appropriate to my role.

---

### Acceptance Criteria:

1.  **Given** a user is on the authentication page (`AuthPage.tsx`),
    **When** they are a new user,
    **Then** they should see a form with fields for `Full Name`, `Email Address`, `Password`, and a `Role Selector` ('Customer' or 'Kitchen Owner').

2.  **Given** a user is on the authentication page,
    **When** they are a returning user,
    **Then** they should see a form with fields for `Email Address` and `Password`.

3.  **Given** a user is on the authentication page,
    **When** they click the toggle link,
    **Then** the view should switch between the "Sign Up" and "Login" forms.

4.  **Given** a user successfully signs up or logs in,
    **Then** an authentication token and user data must be stored securely in the frontend state (`AuthProvider`).

5.  **Given** a user provides incorrect login credentials,
    **Then** a clear error message must be displayed on the form.

6.  **Given** a user attempts to sign up with an email that already exists,
    **Then** a clear error message must be displayed on the form.

7.  **Given** the application's authentication flow,
    **When** a user authenticates,
    **Then** all API requests to protected backend endpoints must include the authentication token.

---

### Technical Specification:

-   This is primarily a refactoring task to align the frontend with the approved backend architecture.
-   The `api/authApi.ts` module must be updated:
    -   The `login` function must make a `POST` request to `/api/v1/auth/login`.
    -   The `signup` function must make a `POST` request to `/api/v1/auth/signup`.
    -   The `logout` function must make a `POST` request to `/api/v1/auth/logout`.
-   The `api/mock.ts` file must be updated to ensure the `mockApiRouter` correctly handles these new `v1` routes, allowing development to proceed without a live backend.
-   No visual or UI changes are required in `AuthPage.tsx` or other components. The existing UI correctly captures all required fields.

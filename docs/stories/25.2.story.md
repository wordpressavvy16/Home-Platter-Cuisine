# Story 25.2: Implement Responsive & Optional Onboarding Flow

-   **Epic:** 25 (UI/UX 2.0 Redesign)
-   **Status:** Done

---

### User Story:
As a new user, I want the freedom to browse the app immediately without being forced to set my location, and I want a different, less intrusive experience on desktop compared to mobile, so that my first impression is frictionless and respects my device context.

---

### Acceptance Criteria:

1.  **[Desktop] Given** a new or logged-out user visits the app on a large screen (desktop/laptop), **Then** they must be taken directly to the `HomePage` to browse, completely bypassing the `WelcomePage` and `LocationPage`.
2.  **[Mobile] Given** a new or logged-out user visits the app on a small screen (mobile), **Then** they must still be shown the `WelcomePage`.
3.  **[Mobile] Given** a user is on the `LocationPage`, **Then** a "Skip for now" button or link must be clearly visible.
4.  **[Mobile] Given** a user clicks "Skip for now" on the `LocationPage`, **Then** they must be navigated to the `HomePage` without their location being set.
5.  **[Permissions] Given** a user is on the `LocationPage`, **Then** the browser's geolocation permission prompt must *only* appear after they explicitly click the "Use my current location" button. It must not trigger on page load.
6.  **[Homepage] Given** a user arrives on the `HomePage` without a location set, **Then** the page must still load correctly, displaying a generic or default set of kitchens instead of showing an error or a blank screen.

---

### Technical Specification:

-   **Routing & Responsiveness (`App.tsx`):**
    -   The main router logic will be updated to include a screen size check (e.g., using `window.innerWidth` or a custom hook).
    -   On initial load, if the screen is large (e.g., > 768px), the router will render `HomePage` directly for the `/` path, regardless of auth or location status.
    -   If the screen is small, the existing flow (`WelcomePage` -> `LocationPage` for logged-out users, `LocationPage` for newly logged-in users) will be used.

-   **Component (`components/LocationPage.tsx`):**
    -   A new `<button>` or `<a>` tag for "Skip for now" will be added.
    -   The `onClick` handler for this new button will call `onLocationSet({})`, signifying a skip, which will navigate the user to the `HomePage`.
    -   The `handleUseCurrentLocation` function must be refactored. Any call to `navigator.geolocation.getCurrentPosition()` must be moved *inside* this function, ensuring it is only triggered by the user's click.

-   **Component (`components/HomePage.tsx`):**
    -   The logic for fetching providers must be updated to handle cases where no location is available in `localStorage`. In such cases, it should fetch a default, un-filtered list of all providers.

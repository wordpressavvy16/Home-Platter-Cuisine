# Story 1.7: Implement User Notification Preferences

-   **Epic:** 1 (Unified User & Onboarding System)
-   **Status:** Done

---

### User Story:
As a user, I want to manage my notification settings in my profile, so that I can choose which types of alerts I receive (e.g., order updates, promotions) and avoid unwanted notifications.

---

### Acceptance Criteria:

1.  **Given** a user is on their `ProfilePage` and navigates to the "Notifications" tab.
2.  **When** they view the page, **Then** a new "In-App Notification Preferences" section must be visible, containing toggle switches for categories like "Order Status Updates," "New Messages," and "Promotions & Announcements".
3.  **Given** a user changes the state of a toggle switch.
4.  **When** the action is performed, **Then** their preference must be saved to their user profile in the backend.
5.  **Given** a user has disabled a specific notification category (e.g., "Promotions").
6.  **When** an event occurs that would normally trigger that type of notification (e.g., a provider sends an announcement), **Then** the notification must not be created or sent to that user.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `User` interface has been updated to include a new optional object: `notificationPreferences?: { orderUpdates: boolean; newMessages: boolean; promotions: boolean; };`.

-   **API Layer:**
    -   **`api/userApi.ts`**: A new function `updateUserNotificationPreferences(userId, preferences, token)` has been created to call a new `PUT /api/users/:id/notification-preferences` endpoint.
    -   **`api/mock.ts`**:
        -   A handler for the new `PUT` endpoint has been implemented to save the preferences to the user object in the mock DB.
        -   All mock API handlers that generate notifications (e.g., for order status changes, new messages, announcements) have been updated to first check the recipient's `notificationPreferences` before creating the notification object.

-   **UI Component (`components/NotificationSettingsPanel.tsx`):**
    -   The component has been significantly enhanced. It is now split into two sections: one for browser push notifications and a new one for in-app preferences.
    -   The new section fetches the user's full profile to get their current preferences, displays the toggle switches, and calls the new `updateUserNotificationPreferences` API on change.
    -   It manages its own loading and saving states to provide a good user experience.

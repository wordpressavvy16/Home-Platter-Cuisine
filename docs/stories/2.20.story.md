# Story 2.20: Scalable Catering & Capacity Management Engine

-   **Epic:** 2 (Provider Storefront & Product Management)
-   **Status:** Done

---

### User Story:
As a small tiffin provider, I want a simple way to manage my limited catering availability (e.g., one event per day). As a professional caterer, I want a robust system to manage my much larger, concurrent capacity (e.g., handling multiple events at the same time). As a customer, I want to see a provider's availability in real-time before I send an inquiry, so I don't waste time contacting a booked-up chef.

---

### Acceptance Criteria:

1.  **Given** a Provider is on their `EditProfilePage`.
2.  **When** they view the "Catering Services" section, **Then** they must be able to choose a "Capacity Management Model": either "Simple Mode" or "Professional Mode".
3.  **Given** the Provider selects "Simple Mode", **Then** they must see an input to define the "Maximum events per service window" (e.g., 1).
4.  **Given** the Provider selects "Professional Mode", **Then** they must see an input to define their "Maximum concurrent guests" (e.g., 500).
5.  **Given** a Customer opens the "Catering Inquiry" modal (`BulkInquiryModal`), **Then** they must select an event date and a service window (e.g., Lunch, Dinner) *before* sending the inquiry.
6.  **Given** the Customer selects a date and window, **Then** the system must perform a real-time availability check against the provider's capacity model and existing bookings.
7.  **Given** the provider is unavailable at the selected time, **Then** a clear "Fully Booked" message must be displayed, and the inquiry submission button must be disabled.
8.  **Given** a catering inquiry is successfully submitted (simulating a booking for this MVP), **Then** a `CateringBooking` record must be created for the provider, which will block their availability for future inquiries at that time.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `MealProvider` interface has been updated with `cateringMode?: 'simple' | 'professional'`, `cateringMaxEventsPerWindow?: number`, `cateringProfessionalCapacity?: number`, and `cateringBookings?: CateringBooking[]`.
    -   A new `CateringBooking` interface has been created.

-   **Provider UI (`components/EditProfilePage.tsx`):**
    -   A new "Capacity Management Model" section has been added with radio buttons to select the mode.
    -   The UI conditionally renders the correct input field based on the selected `cateringMode`.

-   **Customer UI (`components/BulkInquiryModal.tsx`):**
    -   The modal has been overhauled to include date and service window select fields.
    -   It now fetches the full provider profile on open to get the latest `cateringBookings`.
    -   A `useEffect` hook has been added to perform the real-time availability check whenever the date, window, or guest count changes, updating a new `availability` state.
    -   The UI displays the availability status and disables the form if the provider is booked.

-   **API (`api/mock.ts`):**
    -   The `POST /api/inquiries` handler has been updated. When an inquiry is created, it now checks for special `__bookingDetails` in the message payload.
    -   If these details exist, it simulates a confirmed booking by creating a `CateringBooking` object and adding it to the provider's `cateringBookings` array, thus blocking their calendar for future checks.

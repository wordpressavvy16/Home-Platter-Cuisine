# Story 4.8: Intelligent Pre-Order System

-   **Epic:** 4 (Seamless Ordering & Transaction Flow)
-   **Status:** Done

---

### User Story:
As a Customer, if I miss the order cut-off time for the current meal (e.g., lunch), I don't want to hit a dead end. Instead, I want the platform to intelligently offer me the option to pre-order for the next available service window (e.g., dinner on the same day, or lunch tomorrow), so that I can still place an order and the provider doesn't lose my business.

---

### Acceptance Criteria:

1.  **Given** a customer visits a provider's page after the cut-off time for the current service window has passed.
2.  **When** there is another service window available on the same day (e.g., Dinner), **Then** a status banner must inform them that the current window is closed but they can pre-order for the next one (e.g., "Lunch orders are now closed. Pre-order now for Dinner!").
3.  **Given** this "pre-order" state, **When** the customer views a meal card, **Then** the "Add to Cart" button's text must dynamically change to be explicit (e.g., "Pre-order for Dinner").
4.  **Given** the customer adds a pre-order item to their cart, **Then** it must be visually distinguished in the `CartModal`, grouped under a "Pre-Order" heading for that provider.
5.  **Given** the customer checks out with a mix of immediate and pre-order items, **Then** the system must correctly create separate `Order` objects for each unique delivery window.
6.  **Given** a provider receives a pre-order, **Then** it must be clearly marked on their `OrdersPanel` to distinguish it from orders needing immediate preparation.

---

### Technical Specification:

-   **Data Model (`types.ts`):**
    -   The `CartItem` and `Order` interfaces have been updated to include an optional `deliveryWindow?: string;` property.

-   **Component (`components/MealProviderDetails.tsx`):**
    -   The core logic has been refactored into a new, more intelligent `getKitchenAvailability` function.
    -   This function no longer returns a simple boolean but an object containing the kitchen's `status` ('OPEN', 'PRE_ORDER', 'CLOSED'), a user-friendly `message`, and the `nextAvailableSlot`.
    -   This availability object is passed down as a prop to the `MealCard` components.

-   **Component (`components/MealCard.tsx`):**
    -   The component now receives the `kitchenAvailability` object.
    -   The "Add to Cart" button is now dynamic. It changes its text based on the kitchen status and passes the correct `deliveryWindow` string to the `addToCart` function.

-   **State Management (`providers/CartProvider.tsx`):**
    -   The `addToCart` function signature has been updated to accept the optional `deliveryWindow`.
    -   The logic now creates `CartItem` objects that include this `deliveryWindow`.

-   **Component (`components/CartModal.tsx`):**
    -   The rendering logic has been updated to group items within each provider's section based on their `deliveryWindow`, creating clear visual separation for the user.

-   **API (`api/mock.ts`):**
    -   The checkout handler (`POST /api/orders/checkout`) has been refactored. It now groups items in the cart by both `providerId` AND `deliveryWindow`, creating separate `Order` objects for each unique combination. This ensures pre-orders are segregated correctly on the backend.

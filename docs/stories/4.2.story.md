# Story 4.2: Simulate Realistic Payment Gateway Interaction

-   **Epic:** 4 (Seamless Ordering & Transaction Flow)
-   **Status:** Done

---

### User Story:
As a Customer, when I click "Place Order" on the checkout page, I want to see a payment processing modal that simulates a real transaction, so that I have a secure and trustworthy checkout experience that mimics a real-world application.

---

### Acceptance Criteria:

1.  **Given** a Customer is on the `CheckoutPage` and has filled out all the required information.
2.  **When** they click the "Place Order" button, **Then** a new "Confirm Payment" modal must appear instead of the order being placed immediately.
3.  **Given** the "Confirm Payment" modal is open, **Then** it must clearly display the final total amount to be paid.
4.  **Given** the Customer clicks the "Pay Now" button inside the modal, **Then** the modal must display a loading/processing state for a few seconds to simulate the payment gateway interaction.
5.  **Given** the simulated payment is "successful", **Then** the order creation process is finalized, the modal closes, and the user is navigated to the `OrderSuccessPage`.

---

### Technical Specification:

-   **Component Creation (`components/PaymentModal.tsx`):**
    -   Create a new, self-contained modal component that receives `isOpen`, `onClose`, `totalAmount`, and an `onConfirmPayment` callback function as props.
    -   The modal will have its own internal state to manage the `isProcessing` loading status.
    -   When the "Pay Now" button is clicked, it will set `isProcessing` to `true`, wait for a short duration (e.g., 2-3 seconds) using `setTimeout` to simulate a real API call, and then invoke the `onConfirmPayment` function.

-   **Component Refactoring (`components/CheckoutPage.tsx`):**
    -   Add a new state, `isPaymentModalOpen`, to control the visibility of the new modal.
    -   The `handleSubmit` function (triggered by the "Place Order" button) will now prevent its default action and simply set `isPaymentModalOpen` to `true`.
    -   The existing logic for placing the order will be moved into a new `handleConfirmPayment` function.
    -   This `handleConfirmPayment` function will be passed as the `onConfirmPayment` prop to the `PaymentModal` component.
    -   The `CheckoutPage` will render the `PaymentModal` conditionally based on `isPaymentModalOpen`.

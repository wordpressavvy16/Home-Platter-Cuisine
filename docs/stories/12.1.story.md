# Story 12.1: Transform HomePlate into a Progressive Web App (PWA)

-   **Epic:** 12 (Platform Evolution)
-   **Status:** Done

---

### User Story:
As a user, I want to be able to "install" the HomePlate web application onto my device's home screen, so that I can access it quickly like a native app. I also want it to be reliable and provide some basic functionality even if I have a poor network connection.

---

### Acceptance Criteria:

1.  **Given** a user is browsing the HomePlate application on a PWA-compatible browser (e.g., Chrome on Android, Safari on iOS).
2.  **When** they meet the browser's criteria for engagement, **Then** they must be prompted with an option to "Add to Home Screen" or "Install App".
3.  **Given** the user installs the app, **Then** a "HomePlate" icon must appear on their device's home screen or app drawer.
4.  **Given** the user launches the app from its home screen icon, **Then** it must open in a standalone, full-screen window without the browser's address bar, providing an app-like experience.
5.  **Given** the user opens the app while completely offline, **Then** they must be shown a user-friendly offline page instead of a browser's default network error screen.

---

### Technical Specification:

-   **Web App Manifest (`manifest.json`):**
    -   A new `manifest.json` file will be created in the root directory.
    -   It will define the application's name, icons, `start_url`, `display` mode (`standalone`), and theme colors.
    -   The `index.html` file will be updated to link to this manifest file using `<link rel="manifest" href="/manifest.json">`.

-   **Service Worker (`sw.js`):**
    -   A new service worker script, `sw.js`, will be created in the root directory.
    -   The service worker will use a "cache-first" strategy. On install, it will pre-cache essential static assets, including the main `index.html` and a new `offline.html` page.
    -   The `fetch` event listener will intercept network requests. If a request fails (due to being offline), the service worker will serve the `offline.html` page as a fallback for navigation requests.

-   **Service Worker Registration (`registerServiceWorker.ts`):**
    -   A new script will be created to handle the registration of the service worker.
    -   This script will check if `navigator.serviceWorker` is supported by the browser.
    -   It will be called from the main application entry point (`index.tsx`) to register `sw.js` on page load.

-   **Offline Page (`offline.html`):**
    -   A simple, static HTML page will be created to provide a user-friendly message when the user is offline and the requested content is not cached.

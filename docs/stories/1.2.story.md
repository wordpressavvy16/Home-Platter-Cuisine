
# Story 1.2: Provider Onboarding & Profile Setup

-   **Epic:** 1 (Unified User & Onboarding System)
-   **Status:** Done

---

### User Story:
As a new Provider, after I sign up, I want to be guided through setting up my kitchen's profile so that I can list my products and be visible to customers on the marketplace.

---

### Acceptance Criteria:

1.  **Given** a new user signs up with the 'PROVIDER' role,
    **When** their account is created,
    **Then** a corresponding `MealProvider` profile must be created in the system with a status of `isSetupComplete: false`.

2.  **Given** a Provider is logged in and their profile is not yet complete (`isSetupComplete: false`),
    **When** they navigate the application,
    **Then** they must be automatically redirected to the "Edit Profile" page (`DASHBOARD_PROFILE_EDIT`).

3.  **Given** a Provider is on the "Edit Profile" page for the first time,
    **Then** they should see a welcome message prompting them to fill out their details.

4.  **Given** a Provider fills out and saves their profile details successfully,
    **When** the data is updated,
    **Then** their `isSetupComplete` status must be set to `true`.

5.  **Given** a Provider's profile is complete (`isSetupComplete: true`),
    **When** they log in,
    **Then** they should be directed to their main Dashboard, not the "Edit Profile" page.

6.  **Given** a Customer is browsing the `HomePage`,
    **Then** they should only see Providers whose profiles are complete (`isSetupComplete: true`).

---

### Technical Specification:

-   **Backend (`api/mock.ts`):**
    -   The `/api/v1/auth/signup` endpoint must create a default `MealProvider` object with `isSetupComplete: false` when a new user with role 'PROVIDER' registers.
    -   The `GET /api/providers` endpoint must be filtered to only return providers where `isSetupComplete: true`.
    -   The `PUT /api/providers/:id` endpoint must set `isSetupComplete: true` on the provider object after a successful update.

-   **Frontend (`App.tsx`, `providers/AuthProvider.tsx`):**
    -   The `AuthProvider` must fetch and expose the `providerProfile`, including the `isSetupComplete` status.
    -   The main application component (`App.tsx`) must contain routing logic to check for `user.role === 'PROVIDER'` and `isProviderSetupComplete === false`, and if true, force a redirect to the `DASHBOARD_PROFILE_EDIT` route.

-   **UI (`components/EditProfilePage.tsx`):**
    -   The page should display a conditional welcome/instructional message if `isProviderSetupComplete` is `false`.

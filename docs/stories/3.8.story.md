# Story 3.8: Dynamic Content Pages for Footer Links

-   **Epic:** 3 (Customer Marketplace & Discovery Engine)
-   **Status:** Done

---

### User Story:
As a user, I want to click on links in the footer (like "About Us" or "Privacy Policy") and be taken to actual pages with relevant content, so that I can learn more about the company and its policies in a seamless, professional manner.

---

### Acceptance Criteria:

1.  **Given** a user clicks on any link in the application footer (e.g., "About Us").
2.  **When** the action is performed, **Then** the application must navigate to a clean, SEO-friendly URL (e.g., `/#/about-us`).
3.  **Given** the user is on a static content page, **Then** the page must display a consistent layout with a header, footer, and a formatted content area.
4.  **Given** the content for these pages, **Then** it must be sourced from simple Markdown (`.md`) files, completely separating content from the application's code.
5.  **Given** the routing system, **Then** it must be dynamic, capable of rendering any static page using a single component and a content manifest, rather than requiring a new component for each page.

---

### Technical Specification:

-   **Architecture: Markdown-Driven Content System**
    -   A new top-level `content/` directory was created to store page content in `.md` files (e.g., `about-us.md`, `privacy-policy.md`).
    -   A new content manifest, `content/index.ts`, was created to map SEO-friendly URL paths to their corresponding Markdown file "slugs". This `staticPageMap` is the single source of truth for all static routes.

-   **Component: Dynamic Page Renderer (`components/pages/StaticPageRenderer.tsx`)**
    -   A single, reusable component was created to render all static pages.
    -   It receives a `slug` prop from the router, fetches the content of the corresponding `.md` file, and parses it into styled HTML.
    -   A `StaticPageLayout.tsx` component was also created to ensure a consistent look and feel across all these pages.

-   **Routing System Refactor (`App.tsx`, `types.ts`)**
    -   The entire application's routing was refactored from a TypeScript `enum`-based system to a modern, string-based path system (e.g., `/#/profile`).
    -   The main router in `App.tsx` now dynamically checks the `staticPageMap` to handle requests for static pages, passing the correct slug to the `StaticPageRenderer`.
    -   All `navigate()` calls throughout the entire application were updated to use the new path-based system.

-   **Component Integration (`components/Footer.tsx`)**
    -   All links in the footer were updated to be functional `<button>` elements that call the `navigate` function with the correct, SEO-friendly path.

# Story 16.1: Backend - Authentication Service Setup

-   **Epic:** 16 (Live Backend - Authentication & Security Foundation)
-   **Status:** Approved

---

### User Story:
As a Backend Developer, I need to create and deploy a new, standalone Authentication microservice that connects to a real production database, so that the platform has a secure and scalable way to manage user identities.

---

### Acceptance Criteria:

1.  A new backend service project is created (e.g., using Node.js/Express).
2.  The service connects to a real database (e.g., PostgreSQL), separate from the frontend's mock `localStorage`.
3.  The service exposes secure endpoints for `/register` and `/login`.
4.  The service correctly hashes and stores user passwords using a strong algorithm (e.g., bcrypt).
5.  Upon successful login, the service generates and returns a secure JSON Web Token (JWT) with an appropriate expiration.

---

### Technical Specification:

-   **This is a backend-only story. No frontend code will be written or changed.**
-   **Framework:** Node.js with a framework like Express or NestJS is recommended.
-   **Database:** A relational database like PostgreSQL is recommended for its robustness.
-   **Authentication:**
    -   Use `bcrypt` for password hashing and comparison.
    -   Use the `jsonwebtoken` library to create and sign JWTs.
-   **API Contract:**
    -   `POST /register`: Accepts `{ name, email, password, role }`. Returns `{ user, token }`.
    -   `POST /login`: Accepts `{ email, password }`. Returns `{ user, token }`.
-   **Deployment:** The service should be containerized using Docker for portability and deployed to a cloud provider.

---

### Definition of Done (DoD):
-   [ ] Backend service project created.
-   [ ] Database connection established.
-   [ ] `/register` and `/login` endpoints are implemented and functional.
-   [ ] Password hashing is correctly implemented.
-   [ ] JWT generation is correctly implemented.
-   [ ] Story status updated to 'Done' in `changelog.md`.

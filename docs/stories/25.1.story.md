# Story 25.1: Implement the Revamped Welcome & Location Selection Flow

-   **Epic:** 25 (UI/UX 2.0 Redesign)
-   **Status:** Done

---

### User Story:
As a new or returning user, I want to experience a visually engaging welcome screen and a seamless location selection process, so that my first interaction with the application is modern, intuitive, and efficient.

---

### Acceptance Criteria:

1.  **Given** a user is opening the app for the first time or is logged out, **Then** they must be presented with the new "Welcome/Onboarding Screen" instead of the current homepage.
2.  **Given** the Welcome Screen is displayed, **Then** it must show the "Tiffin Time" branding, a compelling tagline, and three feature highlights ("Homemade Goodness", "Local & Fresh", "Easy Delivery").
3.  **Given** the Welcome Screen is displayed, **Then** it must have two clear call-to-action buttons: "Sign Up" and "Log In", which navigate to the `AuthPage`.
4.  **Given** a user is logged in, **Then** they should bypass the Welcome Screen and be taken to the Location Selection screen or the main marketplace.
5.  **Given** a user proceeds from the Welcome Screen (or after login), **Then** they must be presented with the "Location Selection Screen".
6.  **Given** the Location Selection Screen is displayed, **Then** it must have a prominent "Use my current location" button and a text input field to manually enter an area or city.
7.  **Given** the user clicks "Use my current location", **Then** the application must request geolocation permission and (on success) proceed to the main marketplace.
8.  **Given** the user enters a location manually and clicks "Find Tiffins", **Then** the application should proceed to the main marketplace, using the entered location for search context.

---

### Technical Specification:

-   **Routing (`App.tsx`):**
    -   The main router logic will be updated. The default route (`/`) will now need to determine whether to show the new `WelcomePage` (for logged-out users) or the `LocationPage`/`HomePage` (for logged-in users). A simple state in local storage (e.g., `hasSeenWelcome`) could be used to show it only once per session for logged-out users.

-   **Component Creation (`components/WelcomePage.tsx` - New):**
    -   Create a new page component to implement the "Welcome/Onboarding Screen".
    -   This will be a stateless, presentational component with styling to match the mockup, including the food image collage background.
    -   The "Sign Up" and "Log In" buttons will use the `navigate` function to go to the `/auth` route with the appropriate parameters.

-   **Component Creation (`components/LocationPage.tsx` - New):**
    -   Create a new page component for the "Location Selection Screen".
    -   It will include the UI elements from the mockup (map placeholder, input field, buttons).
    -   The "Use my current location" button will use the `navigator.geolocation` API. **Note:** This requires adding the `geolocation` permission to `metadata.json`.
    -   Upon getting a location (either automatically or manually), it should store this location in a global state or `localStorage` and then navigate to the `HomePage`.

-   **Component Refactoring (`HomePage.tsx`):**
    -   This component will now assume a location has already been set and will use it to fetch and display relevant providers. The old search/filter bar might need to be adjusted to accommodate this new flow.

# Story 1.6: Implement User Password Recovery Flow

-   **Epic:** 1 (Unified User & Onboarding System)
-   **Status:** Done

---

### User Story:
As a user who has forgotten my password, I want a way to securely reset it so that I can regain access to my account without having to create a new one.

---

### Acceptance Criteria:

1.  **Given** a user is on the `AuthPage` in the "Login" view.
2.  **When** they look at the form, **Then** a "Forgot Password?" link must be visible.
3.  **Given** the user clicks the "Forgot Password?" link, **Then** the view must change to a "Request Password Reset" form, showing only an email input field and a "Send Reset Link" button.
4.  **Given** the user enters their email and clicks "Send Reset Link", **Then** the view must change to a confirmation screen.
5.  **Given** the confirmation screen is shown, **Then** it must display a message like "If an account with that email exists, we've sent instructions to reset your password" and a "Back to Login" button.
6.  **Given** the user is in the reset flow, **Then** they should have a clear option to navigate back to the main login screen at any point.

---

### Technical Specification:

-   **Component (`components/AuthPage.tsx`):**
    -   The component's internal state will be enhanced to manage different views. A new state, `authMode`, will be introduced with possible values: `'login'`, `'signup'`, `'reset_request'`, and `'reset_success'`.
    -   A "Forgot Password?" button will be added to the login form, which sets `authMode` to `'reset_request'`.
    -   The main render logic will be updated with a `switch` statement based on `authMode` to display the appropriate form or view.
    -   The "Reset Request" view will contain a form that, upon submission, sets `authMode` to `'reset_success'`.
    -   The "Reset Success" view will display the confirmation message and a button to set `authMode` back to `'login'`.
    -   No actual API calls for password reset will be made in this story; the implementation focuses on creating a complete and realistic UI/UX flow.

-   **No API or Data Model Changes:** This is a UI-only enhancement to address a critical user journey flaw. No backend changes are required for this simulation.

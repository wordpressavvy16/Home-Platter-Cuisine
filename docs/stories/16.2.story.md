# Story 16.2: Frontend - Connect to Live Authentication

-   **Epic:** 16 (Live Backend - Authentication & Security Foundation)
-   **Status:** Done

---

### User Story:
As a Frontend Developer, I need to update the application to communicate with the new live Authentication Service instead of the mock API, so that users can register and log in to the real production system.

---

### Acceptance Criteria:

1.  The application's API calls for login (`/api/v1/auth/login`) and signup (`/api/v1/auth/signup`) are now directed to a live backend endpoint (`https://api.homeplatter.com`) instead of the internal mock server.
2.  All other API calls (for providers, orders, etc.) must continue to function by routing to the mock server to prevent breaking the application.
3.  The `api/client.ts` "switch" logic is updated to selectively route requests based on their path.
4.  The `AuthPage.tsx` login and signup forms work seamlessly, sending real network requests to the live backend.
5.  The application correctly handles both successful and unsuccessful responses from the live backend (e.g., displaying an error if the live service is unavailable).

---

### Technical Specification:

-   **API Client (`api/client.ts`):**
    -   The `apiClient` function has been refactored to be path-aware.
    -   It now checks if an incoming request path `startsWith('/api/v1/auth/')`.
    -   If it's an authentication request, it sets a local `useMock` flag to `false` and makes a real `fetch` call to the production `API_BASE_URL`.
    -   For all other request paths, the `useMock` flag remains `true`, and the request is routed to the internal `mockApiRouter`.
    -   This implements a phased migration strategy, allowing services to be switched over one by one.

-   **No other code changes are required.** The existing `authApi.ts` and `AuthPage.tsx` components already use the `apiClient`, so they will inherit this new routing behavior automatically.

---

-   [x] Code implemented as per the technical specification.

-   [x] The rest of the application remains functional by continuing to use the mock API.
-   [x] The application's login and signup functionality now makes real network requests.
